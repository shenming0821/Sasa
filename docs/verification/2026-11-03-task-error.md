# 任务失败提示交互

日期：2026-11-03。

## 行为与范围

- 输入框上方以紧凑卡片显示“任务未完成”和简短说明；API 错误、限流和超时有对应说明，未知错误使用通用提示。
- 技术错误默认收起，通过“错误详情”展开；原始信息可选择复制，长内容限制在 100 DIP 内滚动。
- 重试按钮与标题同排，卡片和输入框之间留 10 DIP；颜色使用当前应用主题。
- 重试通过已有发送流程恢复最近用户请求的文字及图片。已有草稿或会话不满足发送条件时禁用，保留草稿和原始历史。
- 本轮调整呈现和重试入口；服务端返回的失败状态继续由原生 Runtime 判定。

## 验证

- 全量 `./scripts/go test ./... -count=1` 通过，UI 包用时 23.149 秒。
- `./scripts/go vet ./...`、失败提示/重试/发送门禁相关 race 检查、`./scripts/build` 与 `git diff --check` 通过。
- 受控 MyGo UI 覆盖 440/800 DIP 两种宽度、浅深色主题、错误默认收起、点击展开原始错误、重试恢复原请求、Busy 拦截重复提交，以及文字/图片草稿和恢复/离线/不完整状态保护。图片草稿与历史切片独立。
- 用户确认当前任务结束后，通过应用菜单正常退出旧版并重新构建、启动新版 PID 75736，确认原会话及历史可恢复。验收后恢复原有标签和历史搜索状态。
- 隔离原生验收使用 `.cache/task-error-acceptance/` 临时程序、独立 bundle ID 和临时数据目录，直接调用同一 `ui.New` / `Run` 及本次卡片源码，注入固定失败状态。该窗口为受控 UI 夹具，不代表真实模型服务验收；未读取或修改用户原生模型配置。
- 原生浅色确认卡片标题、错误说明、右侧重试及与输入框的间距；点击“错误详情”后显示完整原始错误；深色重复核对标题、正文、边框和展开详情清晰可读。
- 原生输入“保留这份草稿”后，重试按钮立即禁用，草稿保持；清空后按钮恢复。点击重试进入现有发送流程，受控后端明确拒绝创建会话，界面显示“本次未发送”，并将原请求恢复到输入框，未产生真实模型调用。
- 隔离窗口已正常退出。真实服务端失败后的重试未再次调用，图片恢复及历史切片独立性由自动化覆盖。
