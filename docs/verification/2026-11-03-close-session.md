# 关闭会话立即停止与回收

日期：2026-11-03。

## 原因与行为

旧 `closeSession` 仅隐藏标签并设置 30 秒延迟，活动任务不发送中断；回收检查又跳过 Busy 会话，因此关闭后项目列表继续显示“正在执行”，等待 30 秒也不会停止任务。

当前关闭标签立即中断对应会话，发送准备中取消提交。原生终态到达后立即尝试回收；空闲会话直接开始回收。停止失败保留“停止待确认”，不把 RPC 成功当作停止完成。原生后台终端、活动子任务、未确认历史及外部写入者仍受保护，草稿及原生历史继续保留。

中断轮次的工具可能缺少 item/completed，遗留 inProgress / AwaitingFinal 会使旧前置检查永久跳过回收。本次允许关闭并已明确中断的会话进入后端检查，继续由原生 idle、后台终端和子任务状态裁决；普通未结束工具继续保护。

此行为适用于关闭会话页签及 Cmd+W；macOS 主窗口关闭按钮沿用隐藏窗口和后台驻留行为。

## 验证

受控协议测试覆盖 Codex / Claude：空闲关闭立即发起回收；运行中关闭只中断目标会话，其他任务继续；等待原生终态后开始回收；停止失败保留状态；发送准备中取消；回收期间重开先恢复再允许发送；存储失败及删除后不复活。

通过：`./scripts/go test ./...`（最终 UI 21.731 秒）、`./scripts/go vet ./...`、`./scripts/go test -race ./internal/ui ./internal/app ./internal/codex ./internal/claude`（最终 UI 130.038 秒）、`./scripts/build`、`git diff --check`。命令行测试使用临时存储与受控协议，运行中关闭用例包含未报告结束的活动工具，确认原生中断后进入后端检查。
