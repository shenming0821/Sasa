## 依据与实现

按顺序读取仓库规范、初版方案、用户提供的[cdesktop 复核报告](2026-10-27-p6-review-cdesktop.md)及当前接续点，沿 Codex Call/reader/事件队列、UI 发送/交互/历史/模型、app 投影和 SQLite 保存/迁移调用链核对。复核报告为原始只读历史证据，基线和“未执行”描述不代表本轮实现状态。

新增 `internal/agent/`：身份、能力接口、应用事件、兼容投影、单次审批与精确规则建议、独立权限设置、发送前 TurnID/user UUID、原生 ID 映射、请求关联与限额。Codex 通过导出类型别名和原入口包装兼容，原生 RPC 名称/参数、常驻 App Server 和进程组管理保持原有路径。

UI/app 使用 agent 类型，额外 backend 在启动前注册并由创建者管理生命周期。会话路由和事件范围包含 Agent/runtime/session/generation；缺少 Claude 后端不会调用 Codex。模型与原生会话列表缓存从 App 根迁入 session，按实际 cwd/runtime 核对；选择保存 Agent 归属，状态和提问文案使用当前 Agent。当前生产入口只启动 Codex，没有新增未实现的 Claude 产品入口。

SQLite v4 重建 session 唯一约束为 `(agent, thread_id)`，Runtime 按 Agent 绑定规范化 home。旧列归属为 codex，原 JSON payload 和旧 home 保留；迁移前校验和一致性备份，重建及版本提升在事务内完成。空 Agent 通过 `Normalized()` 默认为 Codex，保持旧测试/JSON 兼容。v4 防止旧版程序误读 Claude 记录。

## Linux 静态与 SQL 核对：通过

本机 `command -v go gofmt` 均无结果，未安装 Go 工具链，也未执行任何 Go test/vet/build。全部新增及改动 Go 文件按 gofmt 风格人工/辅助核对缩进、字段对齐和导入分组，`git diff --check` 通过；**未宣称 gofmt 实际通过**。

使用临时 Python 环境中的 `tree-sitter 0.25.2`、`tree-sitter-go 0.25.0` 检查所有新增及改动 Go 文件：语法无错误，导入包名均有引用。该检查不解析 Go 类型、不验证接口实现和依赖兼容，不能替代 Go 编译。最初组合 `tree-sitter 0.26.0` 时遍历工具崩溃，改为 0.25.2 后完成检查；未将工具崩溃视为应用测试失败。

使用 Python 标准库 SQLite，在临时数据库中提取并执行 `migration_v4.go` 的实际 SQL，核对：

- WAL 数据库经 `VACUUM INTO` 得到一致性备份，版本 3、`quick_check=ok`、权限 0600。
- v3 → v4 的 payload 字节、旧 Codex home、旧会话归属保留。
- 相同原生 ID 可分别存于 Codex/Claude；同一 Agent 重复原生 ID 被唯一约束拒绝。
- 多个空原生 ID 通过 NULL 共存。
- 注入旧 Runtime 列不兼容，使第二张表迁移失败，整个事务回滚，版本和 sessions 旧结构保留。

该检查验证 SQL 与 SQLite 行为，没有执行 `modernc.org/sqlite` 驱动或 Go 迁移函数。另用 Python 重算录制 SHA-256，检查同 session、帧 UUID 唯一、message.id 复用与完整终态，结果一致。
