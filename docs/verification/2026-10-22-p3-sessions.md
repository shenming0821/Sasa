# P3 首步：会话隔离与侧栏

日期：2026-10-22。范围：内存多会话、新建/切换、独立界面与后台事件。该记录保留首步当时状态；后续实现、补验和当前边界统一见 [P3 验证](2026-10-22-p3.md)。

## 自动化验证

以下命令通过：

```sh
./scripts/go test ./...
./scripts/go vet ./...
./scripts/go test -race ./...
./scripts/build
```

新增 `internal/ui/sessions_test.go` 覆盖：

| 操作与输入 | 核验结果 |
|---|---|
| 在 `/tmp/first` 发送任务，阻塞 thread/start，切换到 `/tmp/second` 并输入草稿，再放行响应 | 原会话获得原生 thread/turn、有效模型和 cwd；当前会话的目录与草稿保持独立 |
| 两个会话分别执行，向未选中的 thread 注入回复和命令审批 | 回复与待办只进入所属会话，当前任务保持 Busy；另一个 thread 完成不会结束当前任务 |
| 切换后执行原会话的失败回调 | 错误、Busy 和补回草稿只修改原会话 |
| 注入共享连接断开，再创建会话 | 所有会话失效待办、停止接受发送，新建会话继承断线边界 |
| 长消息向上阅读，输入草稿，切换并编辑另一会话，再返回 | 原阅读行与脱离末尾状态保持，草稿与工具展开状态保留；重新挂载的编辑器绑定正确草稿 |
| 在 640×480 组件中任务运行时新建、切回和收起侧栏 | 原任务继续运行，停止按钮可见，侧栏收起后输入仍可用 |

原有界面测试继续覆盖 640×480、1000×760、1600×900 和明暗主题。侧栏展开时，阅读区与输入以剩余内容区域居中；返回最新消息的间距及阴影渐变继续通过原组件回归。

vet 曾发现会话绑定直接复制包含 Markdown 内部锁的 App；最终实现改为只构造持有所属会话、backend、window、shutdown 和派发器的回调接收者，复查通过。
