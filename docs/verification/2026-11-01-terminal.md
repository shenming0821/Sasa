# 主窗口原生终端验证

日期：2026-11-01（Asia/Shanghai）。

## 当前范围

按用户确认的性能优先方向，使用完整 libghostty 1.3.1（源码 `22efb0be2bbea73e5339f5426fa3b20edabcaa11`），通过 AppKit 原生子视图和 Metal 渲染嵌入 Fuyu 主窗口。已移除先前网页原型、ghostty-web、xterm.js、回环 HTTP 服务及 creack/pty 依赖。

入口在 Codex/Claude 图标右侧，每次创建独立终端标签并采用当前工作区目录。通用设置目前只提供 Ghostty；旧原型保存的 xterm 值归一到 Ghostty。切换标签保留 shell 与原生 surface，隐藏时通知 Ghostty 不可见；应用内弹窗显示时让出覆盖区域，关闭后恢复焦点。重启只恢复标签元数据，用户点击“启动终端”后创建新 shell。

## 配置与边界

2026-11-05 补充：原生视图在 backing、窗口和尺寸变化时同步图层 `contentsScale`，禁用隐式缩放动画，并由 AppKit backing 转换计算 Ghostty 的内容缩放与像素尺寸。回归与原生混排检查见[终端文字验证](2026-11-05-terminal-text.md)。

原生库调用 `ghostty_config_load_default_files`、`ghostty_config_load_recursive_files` 和 `ghostty_config_finalize`，使用 Ghostty 自身的路径查找、主题、包含文件及配置语义。新建原生终端时重读配置并更新共享 runtime。Fuyu 覆盖 shell 初始 cwd 为选定工作区，窗口、标签、设置、关闭确认和退出由 Fuyu 管理；独立 Ghostty.app 的窗口装饰与窗口管理设置不应用到 Fuyu。

本机已安装 Ghostty 1.3.1。通过该版本的 `+show-config` 核验的配置为：字体 `M PLUS Code Latin`、主题 `Gitlab Light`、背景 `#fafaff`、前景 `#303030`、光标 `bar`、shell `/opt/homebrew/bin/fish`、工作目录配置 `inherit`。真实 Fuyu 窗口已确认对应字体、浅色主题、竖线光标和 fish 启动；`pwd` 为 `/Users/shenming/Documents/Sync/AI/Fuyu`，`infocmp $TERM` 退出状态为 `0`。用户 Ghostty 配置未修改。

## 构建

`scripts/prepare-ghostty.py` 校验下载的 Ghostty 源码和 Zig 0.15.2，构建原生 dylib，随 bundle 打包主题、shell integration、terminfo 和 MIT 许可证。头文件与源码版本固定匹配，运行时动态加载，无需安装 Ghostty.app。当前构建入口支持 macOS arm64。

本机仅有 Command Line Tools，`xcrun --find metal` 不可用。构建补丁将内置 Metal 着色器源码交给系统 Metal 编译器在运行时编译，保留 Ghostty 自身的 Metal 渲染管线，新增首次 surface 初始化成本。另为 Zig 0.15.2 读取本机新版 SDK 的 arm64e 符号声明建立缓存中的兼容 SDK 视图，系统 SDK 保持原样；缓存内只增加等价 arm64 目标声明。

## 真实主窗口验收

- 正常退出旧版，构建后启动 `bin/Fuyu.app`；确认 1000×760 主窗口可用，最新验收进程 PID `21135`。
- 原生终端为 MyGo 主视图的同级 AppKit 视图，位置跟随工作区区域；可访问性树显示原生文本区域，截图确认主窗口内实际 Metal 画面。
- 终端入口、两独立终端切换与输出保留、中文粘贴、工作区目录、terminfo 查询、通用设置默认 Ghostty，以及 Cmd+, 显示设置时隐藏终端并在关闭后恢复：通过。
- `seq 1 200 | less` 翻页及普通 `q` 退出：通过。发现 AppKit 输入法有时提交与预编辑共享的可变字符串，先复制提交文本再清除预编辑，修复普通字母在 raw 程序中被清空；真实窗口与隔离可变文本提交回归均通过。
- 重启后保留终端标签并要求显式“启动终端”，新 shell 正常启动；关闭已退出 shell 的标签不影响另一终端。
