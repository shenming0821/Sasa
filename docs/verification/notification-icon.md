# 通知应用图标验证

## 问题与修复范围

Sasa 应用包与系统按应用路径读取的图标已经是红橙 Sa，实际后台任务完成通知仍显示旧 Fuyu 图标。仅注销历史应用登记并重启通知中心，未能修复本机的实际显示。

本机保留原图标缓存备份后，重建当前用户的 Icon Services 缓存，并刷新图标服务与通知中心。随后通过正式版的真实 Codex 后台任务触发系统通知，原生通知横幅已显示红橙 Sa 图标。验收没有退出正在运行的正式版。

发布脚本在登记当前应用前，注销 `.Fuyu-releases` 中 Bundle ID 相同的备份应用；保留备份文件和其他渠道的登记。备份尚未登记时返回的注销失败不阻断当前应用登记。此改动消除托管备份的应用身份歧义，不代表能够自动清除所有 macOS 图标缓存；发布入口不执行全局缓存重建。

## 验证结果

- 真实 Runtime：正式版 Codex 验收会话完成任务，切回其他会话后触发完成通知。
- 原生 UI：首次复测仍为旧图标；重建缓存后的通知横幅确认为新版 Sa。
- 自动化：`python3 -B -m unittest discover -s scripts -p test_release.py`，23 项通过。注册回归覆盖旧图标备份、同 ID 的多个备份、其他渠道隔离，以及未登记备份的注销失败。

本机缓存备份位于 `/var/folders/8t/brc73fcs07d1slb8w2wdx66h0000gn/T/sasa-icon-cache-backup-q9__8xyf/store.index`。该临时文件仅用于本机排障恢复，不随应用发布。
