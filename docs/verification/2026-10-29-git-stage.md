# Git 暂存交互稳定性验证

日期：2026-10-29。

## 修改与原因

暂存和取消暂存启动时，原实现插入“正在…”状态行；完成后显示成功提示，并先解除写入保护，再异步读取状态与分支等元数据。列表上方行数变化导致布局移动，按钮还可能先恢复到旧快照。

现在保留当前列表，在同一后台任务中执行写入和真实 Git 状态读取，再一次更新快照并解除写入保护。暂存类操作通过文件分组变化反馈完成，错误仍就地显示。保留最近提交缓存，省去整项目与编辑文件刷新，相关 Diff 使用新快照更新。首次无内容的读取与较长远程操作保留必要提示；项目规则及代码标准约定仅在必要等待时增加 loading。

## 自动化结果

- `TestGitIndexActionsKeepListSteady`：暂存、取消暂存和空闲切换时，文件行位置保持一致；过程无 loading 行；错误可见。
- `TestGitBulkStageAlternatesWithReadySnapshot`：隔离临时仓库两个文件，六次交替点击“全部暂存”“全部取消暂存”。每次按钮恢复时，分组快照与实际 index 一致；无成功提示、无二次状态读取、保留历史缓存。
- 原有后台刷新布局回归及 Git 相关定向测试通过。
- `./scripts/go test ./...`、`./scripts/go vet ./...` 通过。
- `./scripts/go test -race ./internal/ui -run 'TestGit(IndexActions|BulkStage|WorkflowStages|Dirty|Hunk)|TestP4GitBackground' -count=1` 通过。
- `./scripts/build` 通过。

## 原生窗口与边界

通过原生 Command+Q 正常退出旧实例；随后连接新版窗口，核对实例 PID 78029，Git 面板、文件列表、提交框和最近提交入口显示正常，无中间状态提示。已取得原生 AX 和截图。

实际 Git 写入测试均在临时仓库和 MyGo 内存渲染器中执行。原生窗口未对用户仓库执行批量暂存或取消暂存；真实鼠标交替操作的流畅度待用户复核。未发送模型任务。

## 顶部短暂变淡的补充修复

用户反馈去掉提示行后仍有闪动，尤其是分支工具栏、upstream 与提交输入区域。复核发现暂存期间共享 busy 状态仍触发整体禁用和恢复。原来的文件行位置回归仅检查几何位置，没有覆盖颜色和透明度变化。

`TestGitIndexActionsKeepHeaderPixelsSteady` 比较工具栏、upstream、提交输入框和主提交按钮的完整像素，覆盖浅/深色主题、空/非空草稿，逐帧切换暂存、空闲、取消暂存与空闲；四组在修复前均失败，修复后均通过。另验证暂存中仍可编辑提交信息，分支切换入口受到逻辑保护。

快速索引操作现在保留顶部及文件操作的正常外观，保持提交草稿可编辑；重复写入、分支、远程和刷新继续在逻辑入口拦截。保存准备、退出和其他 Git 操作保留原来的禁用行为。

补充修复后 `./scripts/go test ./...`、`./scripts/go vet ./...`、`./scripts/go test -race ./internal/ui -run 'TestGit(IndexActions|BulkStage|WorkflowStages|Dirty)|TestP4GitBackground' -count=1`、`./scripts/build` 与差异检查均通过。连接原生窗口时工具明确返回 Mac 已锁定且无法自动解锁，因此本次尚未正常退出重启或完成原生复核；保留原实例，解锁后继续。

解锁后续验：已通过 Command+Q 正常退出旧实例 PID 42848，确认进程退出后启动新版 PID 27554。原生 AX 与截图确认 Git 工具栏、upstream、提交输入框和文件列表可用，“生成”按钮保持移除。未对用户仓库执行暂存写入；过渡像素稳定性依据上述受控回归，实际交替点击的主观流畅度交由用户复核。
