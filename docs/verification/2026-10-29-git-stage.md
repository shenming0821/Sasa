# Git 暂存交互稳定性验证

日期：2026-10-29。

## 修改与原因

暂存和取消暂存启动时，原实现插入“正在…”状态行；完成后显示成功提示，并先解除写入保护，再异步读取状态与分支等元数据。列表上方行数变化导致布局移动，按钮还可能先恢复到旧快照。

现在保留当前列表，在同一后台任务中执行写入和真实 Git 状态读取，再一次更新快照并解除写入保护。暂存类操作通过文件分组变化反馈完成，错误仍就地显示。保留最近提交缓存，省去整项目与编辑文件刷新，相关 Diff 使用新快照更新。首次无内容的读取与较长远程操作保留必要提示；项目规则及代码标准约定仅在必要等待时增加 loading。

## 自动化结果

- `TestGitIndexActionsKeepListSteady`：暂存、取消暂存和空闲切换时，文件行位置保持一致；过程无 loading 行；错误可见。
- `TestGitBulkStageAlternatesWithReadySnapshot`：隔离临时仓库两个文件，六次交替点击“全部暂存”“全部取消暂存”。每次按钮恢复时，分组快照与实际 index 一致；无成功提示、无二次状态读取、保留历史缓存。
- 原有后台刷新布局回归及 Git 相关定向测试通过。
- `./scripts/go test ./...`、`./scripts/go vet ./...` 通过。
- `./scripts/go test -race ./internal/ui -run 'TestGit(IndexActions|BulkStage|WorkflowStages|Dirty|Hunk)|TestP4GitBackground' -count=1` 通过。
- `./scripts/build` 通过。

## 原生窗口与边界

通过原生 Command+Q 正常退出旧实例；随后连接新版窗口，核对实例 PID 78029，Git 面板、文件列表、提交框和最近提交入口显示正常，无中间状态提示。已取得原生 AX 和截图。

实际 Git 写入测试均在临时仓库和 MyGo 内存渲染器中执行。原生窗口未对用户仓库执行批量暂存或取消暂存；真实鼠标交替操作的流畅度待用户复核。未发送模型任务。
