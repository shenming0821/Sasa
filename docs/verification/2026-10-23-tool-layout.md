# 工具卡片长命令布局验收

日期：2026-10-23。

后续命令展示已调整为[轻量分组折叠交互](2026-10-23-command-disclosure.md)，本文保留原问题、原修复与当时验收证据。当前入口及新像素回归以新记录为准。

## 问题与原因

用户提供的 Fuyu 截图中，历史里的长 Python / shell 命令越过灰色卡片边界，覆盖工作目录、退出码、展开按钮及后续助手消息。属于绘制与占位不一致。

`internal/ui/activity.go` 原先对命令 Text 使用 `MaxHeight(72)`，但该约束只缩小元素布局高度，没有截断实际文字或裁切绘制。卡片外框按受限高度布局，文本仍持续绘制。

## 修复

- 命令预览使用 `MaxLines(4)`，过长时以省略号结束，不再用固定最大高度压缩文字占位。
- 含命令的卡片提供“展开详情 / 收起详情”，即便没有输出也可查看完整命令；源命令保持完整。
- 完整命令、输入、输出和 Diff 在同一最高 180 DIP 的滚动区展示，纯输出卡片保留“展开输出 / 收起输出”。
- 卡片增加绘制裁切，防止子内容越界影响其他消息；布局不会因绘制越界污染列表后续条目。

## 回归证据

新增 `TestLongToolCommandDoesNotPaintOverFollowingMessages`，通过 MyGo 内存渲染器渲染 90 行中英文命令与下一条消息，检查实际 PNG 像素。修复前，在 320 与 800 DIP 宽度下均复现卡片外绘制：后续消息下方 `(16,200)` 附近出现命令文字。

修复后测试通过，覆盖：

- 320 / 800 DIP 宽度与浅色 / 深色主题。
- 命令预览与工作目录元数据的布局顺序、间距内没有命令绘制。
- 后续消息下方留白不出现越界文字。
- 命令没有输出时仍能展开完整详情；详情高度不超过 180 DIP。
- 展开、详情滚动、收起、追加命令文本以及缩放到 480 DIP 后重复验证。

`./scripts/go test ./...`、`./scripts/go vet ./...`、`./scripts/go test -race ./...`、`./scripts/build` 均通过。已有超长展开输出与输入区可用性测试同时通过。

本轮未创建真实 Codex 任务，未更改历史消息、原生命令、会话占用状态或数据库。上述像素证据来自受控内存渲染器；用户提供的截图证明原问题，不能作为修复后的原生窗口证据。最新版已重新构建至 `bin/Fuyu.app`，原生窗口复验待重新启动后执行。
