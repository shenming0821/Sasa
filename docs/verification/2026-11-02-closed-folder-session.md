# 关闭最后一个会话后点击文件夹

## 行为与原因

工作区卡片在显示已有对话摘要时直接选中该对话，绕过文件夹页签选择；`openWorktree` 在没有打开页签时也会从全部会话中复用历史，包含已关闭会话。

卡片点击统一调用 `openWorktree`：有打开页签时使用本组已选页签，没有打开页签时创建空白会话。关闭后保留原对话、草稿及协议归属，用户仍可通过历史入口主动重开。普通目录标题继续控制展开/收起。

## 自动化

- `TestFolderClickCreatesSessionAfterLastTabClosed` 使用 MyGo 内存渲染器点击实际工作区按钮，覆盖空白会话、已有标题及 thread 的会话；关闭后创建空白会话，原草稿保留，再次点击复用打开页签，显式重开历史保留状态。
- 新增回归在仅移除 `openWorktree` 历史回退时，已有对话场景仍失败；统一卡片按钮入口后通过，覆盖此前绕过分组选择的路径。
- 更新两项卡片回归，核对选中空白页签保留、已有后台任务继续运行。
- `./scripts/go test ./...` 通过，UI 包 21.894 秒；包含原有混合页签、同组关闭回退、跨文件夹状态和重启恢复测试。
- `./scripts/go vet ./...`、`./scripts/build`、`git diff --check` 通过。

## 原生窗口

通过原生 Command+Q 正常退出，再启动 `bin/Fuyu.app`。应用恢复原有页签 97（“提交并推送”）；关闭该页签后当前文件夹为空工作区。点击 Fuyu 工作区卡片后出现页签 98（“新会话”）与空白任务输入区，原有对话没有重开。最终保留新会话窗口供用户使用。

本轮没有发送真实模型任务；后台任务保持由受控测试覆盖。
