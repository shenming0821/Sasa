## 原生窗口：受控协议夹具

以下操作使用本地 `fixture.py`，证明 Fuyu 的完整协议到窗口链路，不代表真实模型已触发这些请求：

1. 发送“协议夹具：完整审批与提问”，依次批准命令、批准文件修改、允许本轮网络权限。
2. 每步卡片从待处理变为已解决，下一请求可通过“处理待办（1）”定位；文件摘要为新增 example.txt、+2 −0，权限提交为 `{"permissions":{"network":{"enabled":true}},"scope":"turn"}`。
3. 空表单提交后显示“请回答：布局”，焦点到布局回答；选择“宽松”后再提交，显示“请回答：测试口令”，焦点到秘密输入。
4. 输入仅用于本地夹具的测试字符串，画面显示圆点；修复 AX setter 缓存后再次通过 `setValue` 设置，AX 树仍为 secure text field 且无原文 Value。
5. 提交后进入“本轮已完成”，表单与输入值移除，时间线只显示“回答已发送”。本地脱敏回执中问题 ID 为 `layout` 和 `secret`，秘密值为 `[redacted]`。
6. 命令选择拒绝操作时，工具为“已拒绝”，turn 正常结束；选择拒绝并停止时，turn 为“已中断”。等待审批时按停止，请求失效；缺少独立工具终态时显示“等待工具终态”和核验提示。
7. “大量工具输出”发送 1500 条、每条约 910 字节的增量，持续约 30 秒。640×480 下展开输出并向上阅读，显示截断提示，终态仍为已完成、退出码 0、耗时 30 秒。
8. 另起同类持续输出任务，批准后立即展开，在任务仍“正在执行”时粘贴 `draft-during-output` 并向上滚动；草稿可见、阅读位置离开末尾，停止按钮仍可操作。点击停止后收到“已中断”，草稿保留；夹具故意不发送工具终态，界面显示“部分工具尚未报告结束”的核验提示。

回执位于临时根目录的 `receipts.jsonl`，已对秘密回答脱敏，不将原始问题答案复制进仓库。夹具不会真的修改 example.txt，真实文件结果见下一节。

## 真实 Codex

首轮真实任务已通过原生窗口执行：用 apply_patch 创建 `proof.txt`，批准文件修改后使用 Python 读取并断言内容为 `fuyu-p2-proof\n`。原生命令卡片显示退出码 0，工具输出包含该字符串，turn 完成；磁盘文件字节已独立读取核对为 `b'fuyu-p2-proof\n'`。

该轮发现并修复两项兼容问题：忽略未投影的兼容通知，避免将旧事件中的字符串 error 解析为结构体；新增文件 diff 按原文计数，避免错误显示 +0。对应自动化回归通过。

随后复验曾遇到 initialize 超时，以及 thread/start 返回 `failed to load configuration: timed out waiting for cloud config bundle after 20s`。该失败尚未启动 turn；已补充明确拒绝后的安全重试和不确定提交的保护。重新连接后服务恢复，继续完成：

| 操作 | 原生窗口结果 | 独立结果核对 |
|---|---|---|
| 请求 apply_patch 创建 denied.txt，在文件审批选择拒绝操作 | 新增摘要 +1 −0；审批已解决、处理结果为拒绝；工具已拒绝，turn 完成，回复说明未绕过拒绝 | `denied.txt` 不存在 |
| 请求只读沙箱中的 Python 写文件命令 | 原生命令请求显示实际命令、cwd、原因及允许本次/保存命令规则/拒绝并停止，未凭空补出其他选择 | 第一轮收到 cancel，工具已拒绝、turn 已中断；未创建目标文件 |
| 再次申请该命令，在审批选择允许本次 | 审批已解决；命令已完成，退出码 0；展开输出为 `verified: b'fuyu-command-proof\n'`；最终 turn 完成，无旧兼容通知解析警告 | `command-proof.txt` 精确字节为 `b'fuyu-command-proof\n'`；Python 写入后读回并 assert 成功 |

真实模型未触发的提问、额外权限及写入失败等路径仍按夹具/自动化覆盖报告，不扩大上述真实验收范围。

## 已知边界

- 原生 turn 中断不证明独立后台命令退出；工具终态和进程清理继续分别核验。
- MCP elicitation 按当前设计返回 decline；动态工具调用的执行桥接、持久化、历史恢复和完整 Diff 属于后续范围。
- 当前原生模型尚未实测触发用户问题和额外权限申请；这些路径的证据为协议夹具与组件，不能标为真实模型覆盖。
- 断线后不自动重发审批或任务。重新连接与重开后的历史核验由会话持久化与恢复实现。
