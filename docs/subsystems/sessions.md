# 会话管理

## 会话与归属

`internal/ui/sessions.go` 的每个会话独立持有 `app.State`、列表与精确阅读偏移、草稿、工具展开、弹层和待核验标记。一个应用共享一个 Fuyu 自有 App Server，切换选中会话只切换视图，后台任务、审批和异步回调保持原归属。

侧栏显示稳定任务标题、目录、状态和待办数量。工具栏显示当前目录，运行详情显示原生返回的模型、审批策略和沙箱值。已有任务选择另一个目录时新建会话；空白会话直接设置 cwd。启动参数 cwd 与上次选中会话相同时保留选中项，避免同目录的另一个会话抢占。

`forSession` 只绑定所属会话、传输和主线程派发资源。`thread/start` 成功后，先在主线程登记原生 ID 并保存索引，成功后再发 `turn/start`。后台回调通过 `Window.Update` 更新所属会话。共享断线向全部会话传播；普通事件按原生 thread ID 过滤。

## 历史恢复

应用索引的持久 ID 和界面状态见[存储与恢复](storage.md)。消息和工具正文来自 Codex 原生记录：

1. 启动先加载索引，历史会话显示等待核验，发送保持关闭。
2. `thread/resume(excludeTurns=true)` 获取实际目录、模型、审批策略、沙箱和原生状态。
3. `thread/turns/list(itemsView=full, sortDirection=desc, limit=20)` 加载最新页，反转为时间顺序投影。按原生不透明 cursor 加载更早页，以 item ID 去重。
4. 最新状态明确 idle、turn 有确定终态且不存在未确认提交时，允许在相同 thread 继续新 turn。原生 active、未结束 turn、未知状态和恢复失败保留待核验。

`internal/app/history.go` 重建用户消息、回复及结构化工具，复用现有状态投影。旧 stdio 请求不序列化，旧审批和表单不会重新生效。原 thread 未取得 ID 时不自动重发，用户先浏览原生历史，再显式确认继续。

恢复期间按会话暂存最多 2 MiB / 1024 条事件。快照可能已含缓冲增量，不能再拼接 delta；保留控制事件，对增量缺口重新核验权威条目。缓存溢出保留待核验，不静默显示完整。

更早页加载保持当前 turn、Busy、草稿和新消息；显示仍受 1000 条 / 8 MiB 限制。到达边界时停止加载并显示原因，原生记录继续保留。

## 阅读与界面恢复

保存首个可见原生 item ID、条目内相对偏移和是否跟随末尾。恢复锚点位于旧页时自动向前分页，找到后使用稳定 Handle 恢复长回复内部的精确位置；找不到或达到显示上限时明确说明边界。已加载条目的工具展开状态更新索引，尚未加载条目的旧值继续保留。

标题优先使用已保存摘要，避免分页窗口变化后标题随首条可见用户消息改变。草稿和选中会话、侧栏开关均从索引恢复。

## 关闭与退出

`internal/ui/lifecycle.go` 在关闭窗口时保存并隐藏；Fuyu 与后台任务继续运行。Dock 的“打开 Fuyu”或再次激活应用显示原窗口。

退出时先保存；有活动任务时列出所有受影响会话和目录。选择“停止任务并退出”后，逐个发送中断并等待原生终态，等待期间禁止新发送。10 秒后仍未确认时提供“返回核验”与“强制退出”。连接丢失保留不确定性，不能当作停止终态。强制退出前保存未确认任务标记，重开后继续核验。

结束应用关闭自有 App Server 并清理原进程组；独立进程组的后台后代不在当前保证范围。历史恢复不代表重新附着旧 stdio 执行。

## 验证入口

`sessions_test.go` 覆盖多会话归属、异步切换和后台交互；`recovery_test.go` 覆盖重开、原生历史、草稿、分页、条目内锚点、稳定标题和不确定提交；`lifecycle_test.go` 覆盖多任务中断、等待终态、断线边界和超时选择。

实际原生窗口、受控协议及真实模型分别记录在 [P3 验证](../verification/2026-10-22-p3.md)。
