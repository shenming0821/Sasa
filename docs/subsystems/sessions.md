# 会话管理

## 主内容区分屏

主内容区按文件夹 / Worktree 保存独立的面板树。右键面板标题栏或内容空白处，或点击页签栏的“面板操作”，可选择“左右分屏”“上下分屏”；仅切分当前面板，新面板位于右侧或下方，初始均分空间。分隔线复用 MyGo 原生 Split，支持拖动及聚焦后的方向键调整；面板小于 640×220 DIP 时禁用左右新增，小于 320×440 DIP 时禁用上下新增，已有布局在小窗口中继续保留比例。

新面板展示居中的内容选择区：顶部的当前文件夹胶囊徽标、标题、简短说明、三个等宽的整行入口（Codex、Claude Code、终端）和页签拖入提示，内容区宽度最多 360 DIP，随窄分屏收缩。无页签时标题栏左侧留白，保留右上角面板菜单及按需显示的侧栏切换入口。创建失败在入口下显示错误，保留面板并通过原动作重试。每个面板拥有独立页签组与当前页签，同一会话或文件视图只归属一个面板。拖入已有会话时保留任务、草稿和阅读状态；侧栏选择已打开会话时定位所属面板，其余会话在聚焦面板打开。文件和 Diff 在聚焦面板打开，已有文件视图迁移到该面板。

点击面板或输入区更新聚焦面板，保持面板原有外观；当页签拖动到目标面板时显示主题色边框提示落点。主线程在逐面板构建时临时绑定其选择，构建结束恢复布局记录的焦点；编辑按键与粘贴回调固定所属面板，异步协议工作继续使用 `forSession` 固定会话资源。原生终端按可见面板集合显示，并独立维护边界与键盘焦点。快速打开文件（`⌘P`）使用独立透明 MyGo 浮层，终端保持显示与原有尺寸，键盘输入交给搜索面板；关闭后，仍选中的原终端恢复焦点。设置、图片预览等主界面内浮层打开时隐藏终端。

当用户拖动会话、文件、Diff 或终端页签到其他分屏面板时，以主题色加粗边框标记目标，松开后只移动该页签并聚焦目标内容；Esc 取消拖动，在原面板松开保持归属。移动复用原资源，保留任务、草稿和阅读状态；源面板选中剩余页签，移空后保留内容选择入口。面板菜单提供分屏操作。拖动期间暂时隐藏原生终端视图，使终端面板正文也能接收页签，松开或取消后恢复可见终端。布局与页签归属随快照保存。

关闭会话页签调用原有停止流程：立即请求中断，收到 Runtime 终态后才确认停止，历史和草稿保留。关闭终端直接结束其 shell 和任务，不再二次确认。`⌘W` 先关闭弹层，再关闭聚焦面板当前页签；布局多于一个面板且聚焦面板最多只有一个页签时，`⌘W` 沿用面板关闭流程，关闭页签后移除该面板并聚焦相邻面板，仅剩一个面板时不移除。

面板菜单中的“关闭窗口”依次关闭触发时该面板内的页签，会话、文件和终端分别沿用原有关闭行为；仅剩一个面板时不显示该入口。未保存文件支持保存、不保存或取消，终端直接结束 shell；取消、保存失败或文件正在保存时保留面板及尚未关闭的内容，已关闭的页签保持关闭。确认期间新增或移入的页签保留，移出的页签由目标面板管理。页签全部关闭后移除该面板并展开同级剩余布局，优先聚焦布局顺序的前一个面板、否则后一个；最后一个面板保留为空面板。关闭不会将页签迁入相邻面板。

实现入口为 `internal/ui/panes.go`、`panes_view.go`；布局恢复与验证边界见[存储与恢复](storage.md)、[分屏验证](../verification/2026-11-03-split-panes.md)。

当用户从主输入框发送新消息（包括图片与失败重试）且本地发送检查、状态保存通过时，主动滚动到会话底部并恢复后续输出跟随。用户再次向上阅读后，流式更新保持阅读位置。编辑历史消息沿用原位编辑的定位规则。

历史面板的“当前项目 / 全部项目”使用原生分段选择语义与键盘操作，选中底色复用应用按钮的主题 SurfacePressed，悬停与按下沿用统一颜色反馈，适配浅深色；筛选范围与切换行为保持一致。

## 每轮处理用时

从本地发送开始计时，包含发送准备、审批等待、工具执行与回复输出。计时固定在该轮用户问题下一行、全部回复和工具记录之前：进行中复用主线程维护调度，每秒刷新“已处理 3分钟 44秒”；收到原生完成、失败、中断终态或连接断开时冻结，并在同一位置改为“用时 5分钟 9秒”。发送失败也冻结，不把请求成功视为任务完成。两种状态共用主题次要文字与细分隔线，分隔线与下一条记录使用普通的 12 DIP 行间距，组件下方不叠加额外留白。回复、命令或工具输出不会改变计时位置，无回复时也保持同一位置；“正在思考”仍按首条有效输出结束原有等待提示。

用时以 `app.TurnTiming` 关联本轮用户消息，取得原生 turn ID 后按 ID 存入本地会话元数据 `TurnTimings`。恢复与历史分页将用时关联到原生用户消息，兼容消息 ID 变化。未记录计时的旧历史保持原样；重启时尚未取得结束时刻的任务不推算完成用时，原生任务状态核验保持独立。断线冻结值仅表示本地观测时长，任务结果仍按原有待核验状态展示。完成与空闲会话停止每秒刷新。

计时结束后，将“用时”文字与右侧项目既有 `chevron` 箭头作为同一个点击区域控制执行过程：收起朝右、展开朝下，无障碍名称说明具体动作。默认使用次要灰色，悬停或键盘焦点时使用正文色（浅色主题下变黑，深色主题下使用可读的主题正文色），悬停和按下均保持透明背景。每轮默认收起，仅保留用户问题与该轮最后一条非空助手回复。展开后恢复该轮全部中间回复、命令、工具、文件变更与交互记录；运行中持续展示过程。折叠仅影响 UI 投影，原生消息、工具展开状态与任务结果保持完整，各轮及各会话独立。未记录计时的旧历史继续完整展示；新建恢复实例默认收起，当前会话内保留手动选择。恢复阅读锚点落在隐藏过程时定位到所属用户问题。实现见 `internal/ui/turn_timing.go`、`conversation_cache.go`、`commands.go` 与 `history.go`，验证见[执行过程折叠](../verification/2026-11-02-turn-process.md)。

展开与收起共用每轮 200 ms 过渡，过程行的高度、透明度与箭头旋转同步变化，最终回复随过程高度移动。收起结束后再移除过程行，中途反向点击从当前进度继续；首屏历史直接显示收起状态，系统开启减少动态效果时直接切换。

手动展开或收起时，暂停列表的底部跟随，保留当前阅读锚点与偏移；过渡完成并稳定布局后释放暂停。减少动态效果下的即时切换采用相同规则。首次打开会话仍定位到底部，运行时的新输出及“返回最新消息”继续沿用正常跟随规则。MyGo 隔离兼容补丁让 `FollowEnd=false` 在列表同步阶段清除旧跟随状态，避免首次变高时仍按旧状态跳到底部。

## 会话与归属

`internal/ui/sessions.go` 的每个会话独立持有 `app.State`、列表与精确阅读偏移、草稿、工具展开、弹层和待核验标记。一个应用共享一个 Fuyu 自有 App Server，切换选中会话只切换视图，后台任务、审批和异步回调保持原归属。

`internal/ui/projects.go` 将已识别 Git 目录按仓库和 worktree 分组，点击工作区复用对应目录的已有会话，或创建独立新会话；每个工作区支持多个会话，所属 cwd 随新建固定。普通目录由 `internal/ui/navigation.go` 按完整路径分组，同名目录保持独立。项目扫描与异常边界见[项目管理](projects.md)。侧栏默认宽 240 DIP，可拖动调整至 200–320 DIP；搜索标题与完整路径，搜索期间展开匹配的项目，清空搜索后恢复折叠状态。会话显示稳定标题、运行/失败状态和待办数量。顶部标签显示已打开的会话，保存打开列表并在重启后恢复，横向滚动，选中项切换时滚入可见区域；新会话和项目导航均使用已有会话归属逻辑。每个标签右侧提供独立关闭按钮，关闭后保留侧栏记录、草稿、阅读位置、工具状态与后台任务；重新点击项目会话或原生历史可打开。关闭当前标签时优先切换左邻已打开标签，再选右邻；关闭最后一个标签时显示空白主窗口，不创建新会话；保留侧栏和新建入口，历史与后台任务继续保留。已加载会话在本进程内保留状态，重开无需重复恢复；关闭期间恢复回调仅更新原会话，不重新打开标签或抢占当前选择。

工具栏显示当前目录，运行详情显示原生返回的模型、审批策略和沙箱值。已有任务选择另一个目录时新建会话；空白会话直接设置 cwd。常规启动恢复上次选中项与已打开标签；显式启动参数 cwd 不同时按原有目录选择规则打开对应会话，保留其他已恢复标签，避免同目录的另一个会话抢占。

右侧历史默认收起，展开后始终作为窗口内部的侧栏，与中间会话并排。文件、会话历史和 Git 共用右侧宽度，默认 320 DIP，可拖动与主窗口之间的分隔线调整至 240–520 DIP；分隔线的拖动与键盘方向键调整复用左侧的 MyGo Split，悬停与按住时保持普通边框色，不作主题色高亮。空间允许时为中间会话保留至少 400 DIP，640 DIP 窗口下右侧保持最小 240 DIP。窄窗口临时缩小右侧，不覆盖用户的首选宽度，窗口变宽后恢复。支持当前目录/全部项目筛选与已加载标题/路径搜索；分页继续使用原生 cursor，搜索范围明确限于已加载记录。打开已有 thread 时切换对应本地会话，历史侧栏保持展开。

窗口不足以同时放下左侧项目、历史和 400 DIP 会话区域时，优先收起左侧项目；工具栏可临时展开项目导航，选择会话后项目面板收起。历史侧栏随用户开关保持显示，不覆盖消息和输入区。主动开关、侧栏宽度和项目折叠偏好存入现有 JSON 设置，旧数据库缺失字段使用默认值，无须 SQL 迁移。

主聊天区顶栏显示工作目录与侧栏切换入口，所有会话阶段文字（包括就绪、执行中及本轮完成）统一从该位置移除；内部状态、侧栏状态与任务操作继续沿用原有机制。

每侧保留一个切换按钮，提示和无障碍名称分别为“切换左侧边栏”和“切换右侧边栏”。侧栏展开时按钮位于对应侧栏顶部，右侧同样使用侧栏图标；侧栏收起时按钮移到主聊天区顶栏。窄窗口临时项目面板遵循相同规则。

`forSession` 只绑定所属会话、传输和主线程派发资源。`thread/start` 成功后，先在主线程登记原生 ID 并保存索引，成功后再发 `turn/start`。后台回调通过 `Window.Update` 更新所属会话。共享断线向全部会话传播；普通事件按原生 thread ID 过滤。

## 消息送达与快速中断

Codex 本地用户气泡建立时在内部记录待确认状态，界面保持普通用户气泡；`turn/start` 的响应和 `turn/started` 只表示轮次建立。收到同轮原生 `userMessage` 条目后才确认送达。尚未确认输入的轮次结束时，通过 `thread/read(includeTurns=true)` 读取本轮完整条目；核验期间保留消息和用户正在编辑的草稿，核验明确前暂停下一次发送。

原生记录含用户条目时保持已送达，不恢复为待重发内容；完整终态中没有用户条目时，将原气泡标为“未发送”，在输入框没有新文字或图片时恢复原文字和图片，供用户重新发送。已有新草稿时保留新内容并提示原消息未发送。核验失败、缺少轮次或条目不完整时保留不确定性，提供“重新核验结果”，确认后再开放发送。准备阶段明确未提交的取消与失败也标记为未发送。所有异步写回按原会话归属，恢复后的草稿沿用现有持久化。

实现位于 `internal/app/submission.go`、`state.go`、`snapshot.go` 和 `internal/ui/app.go`；消息状态由 `internal/ui/view.go` 就地呈现。实际覆盖及原生限制见[快速中断送达验证](../verification/2026-11-02-interrupted-submission.md)。

## 对话刻度导航

`internal/ui/conversation_navigation.go` 在至少有两条已加载用户消息时，在正文左侧显示固定 36 DIP 轨道。每条用户消息对应一个刻度，复用 `conversationRows` 的真实列表索引，工具分组不产生额外刻度。导航条目与消息行一起缓存，预览读取原消息对象，因此流式文字更新无需重建整组导航。

鼠标靠近时，当前刻度变深，左端固定并向右从 8 DIP 延伸至 16 DIP，相邻刻度按距离减少延伸量；悬停选中刻度额外加长 2 DIP，最大宽 18 DIP。鼠标移出轨道后，所有刻度恢复 8 DIP，当前轮次仅以颜色区分；键盘预览保持统一长度。宽度过渡为 100 ms，系统减少动态效果开启时直接切换。悬停浮层展示用户问题和该问题最后一条助手回复的摘要，标题最多两行、回复最多四行。目标刻度对齐标题与回复之间 8 DIP 空白区的垂直中心，按标题实际一行或两行高度定位；无回复时对齐标题中心。悬停刻度右端与浮层相隔 9 DIP；靠近视口边缘时优先保留标题可见，回复按剩余高度裁切。移出轨道即收起；预览与放大保持正文及输入区位置，直接展示已有内容。

正文滚动到最底部时，位置高亮指向最后一条用户消息；离开底部后按视口顶部所属轮次高亮。悬停或键盘预览期间优先显示选中的预览目标，收起后恢复位置高亮。

点击刻度定位到对应用户消息并解除最新消息跟随，沿用“返回最新消息”恢复跟随。轨道可键盘聚焦，上下键预览相邻问题，Home/End 预览首尾，Enter/Space 定位，Escape 收起预览；无障碍值包含当前轮次与问题摘要。选择按消息 ID 绑定，历史向前追加时保持原目标；空会话不显示导航，切换会话使用各自状态。导航覆盖当前已加载历史，更早内容沿用原有向上分页，加载后补入刻度。Codex 与 Claude Code 共用这一投影与交互，验证见[对话导航验证](../verification/2026-10-29-conversation-navigation.md)。

## 历史恢复

应用索引的持久 ID 和界面状态见[存储与恢复](storage.md)。消息和工具正文来自 Codex 原生记录：

1. 启动只读取索引元数据，恢复保存的打开标签和选中项；只为选中会话请求原生历史，其他已打开标签在首次点击时恢复。关闭的会话保留在项目侧栏，点击时重新打开。旧记录缺少打开列表时，仅打开选中项；不存在的标签 ID 忽略，选中项失效时回退到有效已打开标签。未加载会话保留草稿和历史状态，不批量请求 `thread/resume`。未确认任务显示“上次任务待核验”，发送在实际核验前保持关闭。
2. `thread/resume(excludeTurns=true)` 获取实际目录、模型、审批策略、沙箱和原生状态。
3. `thread/turns/list(itemsView=full, sortDirection=desc, limit=20)` 加载最新页，反转为时间顺序投影。向上滚动到接近顶部时，按原生不透明 cursor 自动加载更早页，以 item ID 去重并保持当前阅读位置；主窗口不显示手动加载按钮。内容不足一屏时继续补页；加载失败后保留已有历史与错误提示，离开顶部再返回可重试。
4. 最新状态明确 idle、turn 有确定终态且不存在未确认提交时，允许在相同 thread 继续新 turn。原生 active、未结束 turn、未知状态和恢复失败保留待核验。

`internal/app/history.go` 重建用户消息、回复及结构化工具，复用现有状态投影。旧 stdio 请求不序列化，旧审批和表单不会重新生效。原 thread 未取得 ID 时不自动重发，用户先浏览原生历史，再显式确认继续。

恢复期间按会话暂存最多 2 MiB / 1024 条事件。快照可能已含缓冲增量，不能再拼接 delta；保留控制事件，对增量缺口重新核验权威条目。缓存溢出保留待核验，不静默显示完整。

### 被其他应用占用

当原生 `thread/resume` 返回对应 thread 的 `-32600: thread <id> already has an active writer` 时，将该会话标为外部占用。通过 `thread/read(includeTurns=false)` 读取元信息，再用现有分页接口加载只读历史。其他错误保持原有恢复失败语义；历史读取失败时保留占用卡和已有消息，显示具体读取错误。

底部使用锁图标、“已在另一个应用中打开”和“请先在那边关闭会话，才能在这里继续。”提示卡，替代输入框和通用恢复入口。“重试”重新核验原会话；占用释放且原生任务终态明确后恢复输入。重试期间保留提示卡，两个操作禁止重复触发。占用状态不会将外部任务变为 Fuyu 的 Busy、审批或退出中断目标；相关事件不会授予写入控制。

“创建聊天分叉”调用 `thread/fork(excludeTurns=true, deferGoalContinuation=true)`，建立独立原生 ID 和本地会话，立即保存索引，再分页加载返回会话的历史。直接使用 fork 返回的状态与配置，保留目标延后续跑状态，等待用户显式发送任务。原会话和草稿保留，草稿同时复制到分叉；异步完成时仅在用户仍查看原会话的情况下切换到新标签。失败保留原会话；连接丢失等结果不确定时暂停重复创建，提示从原生历史核验。

外部占用由每次恢复重新核验，不单独持久化。保存占用视图时保留已有的本地未确认提交标记，避免仅因外部占用而制造新的提交不确定性；阅读位置与工具展开仍按现有方式保存。

更早页加载保持当前 turn、Busy、草稿和新消息；显示仍受 1000 条 / 8 MiB 限制。到达边界时停止加载并显示原因，原生记录继续保留。

## 阅读与界面恢复

任务执行失败时，输入框上方通过 `internal/ui/task_error.go` 展示紧凑提示卡：标题为“任务未完成”，正文按已知错误类型提供简短说明；原始错误放入可用键盘展开、可选择复制的“错误详情”，长内容在卡片内滚动。重试按钮与标题同排，卡片与输入框保留间距，配色跟随应用主题。

“重试本次任务”恢复最近一条用户消息的文字和图片，再经过现有发送流程提交。输入框有文字或图片草稿时保留草稿并禁用重试；运行中、离线、结果不完整、恢复核验、资源释放与退出等状态沿用发送限制。错误详情在切换会话或错误内容变化时收起。验证与接续见[失败提示交互验证](../verification/2026-11-03-task-error.md)。

正常恢复历史后直接显示对话；需要核验旧任务、恢复失败或阅读位置异常时显示对应提示。

Claude 本地命令被旧版本误记为 unknown 时，后端根据同一发送身份的原生本地输出、命令参数及未改变的历史摘要核验完成，再恢复输入；核验不会重发旧任务。行为边界见[Claude 运行时](claude-runtime.md)，本机实际恢复见[本地命令恢复验证](../verification/2026-10-29-claude-local-command-recovery.md)。

保存首个可见原生 item ID、条目内相对偏移和是否跟随末尾。恢复锚点位于旧页时自动向前分页，找到后使用稳定 Handle 恢复长回复内部的精确位置；找不到或达到显示上限时明确说明边界。已加载条目的工具展开状态更新索引，尚未加载条目的旧值继续保留。

标题优先使用用户设置的 `storage.Session.CustomTitle`，其次使用已保存摘要，避免分页窗口变化后标题随首条可见用户消息改变。草稿和选中会话、侧栏开关均从索引恢复。

### 重命名会话

会话标签、项目会话行和右侧历史行共用右键菜单，提供“重命名”和“删除会话”。重命名弹窗预填当前标题，保存或 Enter 确认；取消、Escape、Command+W 及点外部关闭时保留原标题。标题去除首尾空白，空标题或含控制字符时在弹窗提示并保留输入。

`internal/ui/session_rename.go` 将自定义标题保存在 Fuyu 索引，不修改原生 Runtime 历史。保存后标签、项目会话行、历史展示及搜索使用同一标题，分页、继续对话和重启均保留。尚未打开的原生历史先按 Agent、Runtime、ThreadID 查找已有会话；首次改名时仅建立关闭的本地记录，不切换会话或启动恢复。后续打开复用该记录；相同 ID 的其他 Agent/Runtime 独立。运行中也可修改标题，不改变任务、草稿和目录；保存失败回退原标题并保留弹窗。新增字段存于现有 JSON 记录，无需数据库迁移。验证见[重命名验证](../verification/2026-10-29-session-rename.md)。

输入候选位于 `internal/ui/completion.go`。`/new`、`/resume`、`/status`、`/skills` 执行本地已有动作；`$` 使用当前 cwd 的原生技能目录，支持筛选、键盘和鼠标选择，输入法组合期间暂停候选确认。候选浮层不取得输入焦点；选中技能只替换光标前 token，并继续编辑。目录在空闲时预加载，由同 Agent/Runtime/cwd 的会话共享；技能选择归属会话，选择的名称/路径随草稿保存，发送仅附带仍在草稿中的引用。缓存失效、刷新与失败行为见[使用性能与后台维护](performance.md)，原有交互见[输入候选验收](../verification/2026-10-23-input-completion.md)。

`@` 在空白或行首后触发文件候选，查询可含 `/` 以按路径筛选；`internal/ui/completion_files.go` 经 `workspace.Index` 一次收集工作区可见文件与目录（沿用忽略规则与遍历上限，不含 node_modules 等依赖目录），结果按会话 cwd 缓存 60 秒，候选浮层提供刷新。候选按“文件名命中、路径深度、路径长度”排序，最多展示 50 项；选中文件插入 `@相对路径 `，选中目录插入 `@目录/` 并保持 token 激活以继续下钻。`@路径` 作为普通文本随消息发送：Claude Code 原生展开 `@` 引用，Codex 与其 TUI 一致由模型按路径读取；不打包文件内容、不新增协议字段。

Claude Code 会话的 `/` 按当前会话 cwd 加载原生目录，展示 `get_skills_dialog` 确认且出现在 initialize 命令目录中的可调用技能，按技能名称及显示名称关联，排除关闭的技能；另提供本地 `/clear`，`/model`、`/compact` 等其他命令暂不展示。候选与技能共用同 Agent/Runtime/cwd 的应用缓存，标题为“技能与命令”，后台读取时保持安静，读取完成后展示候选或空结果，失败保留上次结果并显示错误与重试；重新读取时清除旧错误，确认候选后把 `/名称 ` 作为普通文本插入草稿，发送时执行。技能交给 Runtime；`/clear` 在本地保存旧历史、关闭旧标签并打开空上下文的新会话，保留 Claude 后端、工作目录和选中模型，后续发送创建新的原生会话。仅在会话可发送且没有图片附件时执行，保存失败时保留原会话，当前只支持不带参数的 `/clear`。Codex 技能候选同样使用安静的后台读取。详见 [Claude 技能候选验证](../verification/2026-10-29-claude-slash-commands.md)及 [/clear 验证](../verification/2026-10-29-claude-clear.md)。

## 关闭与退出

Command+W 与“文件 → 关闭当前页签”共用 `closeCurrentPage`：有文件操作、重命名、设置或图片预览弹层时先关闭弹层；否则关闭当前会话、文件、Diff 或终端标签。未保存文件沿用保存确认，活动会话关闭后继续运行，终端关闭时清理自身 shell。最后一个标签关闭后保留空工作区，再按快捷键保持窗口可见。原生菜单显式绑定页签动作，避免 macOS 默认 File 菜单的 `performClose:` 抢先隐藏窗口。退出或保存确认期间保持当前状态。

关闭 Codex 或 Claude 会话标签时立即请求停止该会话的活动任务；尚在发送准备阶段时取消提交，已取得原生 turn 时发送中断，侧栏显示“正在停止”。原生终态明确后立即尝试回收；空闲会话在关闭时直接开始回收。中断失败显示“停止待确认”，保留真实任务状态和资源。恢复中的会话等恢复完成后再处理停止，外部写入者不纳入停止目标。回收前保存草稿及阅读信息，确认原生空闲、历史可恢复且没有后台工具/终端后释放消息与渲染缓存。Codex 取消原生订阅；Claude 关闭并等待自有空闲进程退出。重开已回收会话时先恢复历史，再开放发送；卸载期间重开等待回收完成，避免与恢复、发送并发。具体边界与失败重试见[使用性能](performance.md#长会话与文件事件)，本次验证见[立即关闭回收](../verification/2026-11-03-close-session.md)。

`internal/ui/lifecycle.go` 在关闭窗口时保存并隐藏；Fuyu 与后台任务继续运行。Dock 的“打开 Fuyu”或再次激活应用显示原窗口。

退出时先保存；有活动任务时列出所有受影响会话和目录。选择“停止任务并退出”后，逐个发送中断并等待原生终态，等待期间禁止新发送。10 秒后仍未确认时提供“返回核验”与“强制退出”。连接丢失保留不确定性，不能当作停止终态。强制退出前保存未确认任务标记，重开后继续核验。

结束应用关闭自有 App Server 并清理原进程组；独立进程组的后台后代不在当前保证范围。历史恢复不代表重新附着旧 stdio 执行。

`internal/ui/tool_details.go` 为 MCP、动态工具和网页搜索提供默认折叠的单行记录。优先读取输入的 `title` 作为动作说明，缺少时显示工具名称；点击整行或键盘操作展开与收起，复用原工具的 `Expanded` 状态与既有索引恢复。命令组与工具记录共用 `processDisclosure`：30 DIP 行高，左侧 16 DIP 图标和标题同级对齐，命令使用带短横线的终端窗口图标，工具使用四方块图标；箭头位于标题右侧，悬停或键盘聚焦时显现，复用 MyGo 的展开动画、键盘及减少动态效果行为。过程标题、耗时、状态与详情统一使用灰色次要文字，命令标题使用常规字重。运行中显示进度和实际状态，成功时只保留耗时，失败/拒绝通过状态文字说明；失败折叠态保留两行错误摘要。命令组与未成功的文件修改继续使用各自现有呈现。

展开内容以轻边框浅色背景区分，包含工具名、输入和结果。带 `code` 的输入将代码单独显示，其余参数保留（标题已用于动作说明）；每块可复制。输入代码横向滚动，普通结果自动换行，每块纵向最大 280 DIP，长内容内部滚动。

结果只展开已识别的 `content`/`text` 文本包装，最多递归十六层；文本中的 JSON 字符串按结构解码换行和制表符。附加字段保留在解码内容之后，非文本块、格式错误或截断数据保留原文/JSON，避免丢失信息。`isError` 返回保持错误状态；展示格式化不改写协议原始消息。截断始终可见。连续工具调用本轮仍分别展示。聊天列表由 `conversationSpacing` 按相邻行类型确定留白：相邻命令组/工具记录之间为 4 DIP，正文、过程记录及文件变更卡片之间为 12 DIP，用户消息前后为 24 DIP；首行不添加额外留白。正文与复制按钮间为 4 DIP，复制按钮为 24 DIP。虚拟列表使用实际行高测量，稳定消息 ID 与阅读锚点机制保持不变。

验证见[工具记录验证](../verification/2026-10-27-tool-details.md)。

聊天 Markdown 的无序列表标记列最多 1.4 em（当前字号 15 DIP，对应 21 DIP），圆点与正文更紧凑，嵌套层级及换行缩进沿用原渲染。有序列表保留 3 em 编号兼容宽度，流式与完成态使用相同设置。实现见 `scripts/mygo-input-style.py`，编号和无序列表回归见 `internal/ui/app_test.go`。

### 用户提问排版

用户消息使用可选择的原生纯文本，字号 15 DIP、字重 400、行高 1.6 倍（24 DIP），气泡上下内边距 8 DIP、左右 16 DIP，圆角 20 DIP；沿用统一中英文字体配置、主题文字颜色与底色，最大宽度为阅读列的 85%，右对齐。原始换行、编号、路径与消息内容保持原样，长连续英文自动换行；不将用户输入解释为 Markdown。

### 默认中英文字体

`internal/ui/fonts.go` 嵌入并注册未修改的 `M PLUS Code Latin` 可变字体，统一窗口主题与 Markdown 正文默认字体；代码、命令、编辑器、冲突与 Diff 使用同款拉丁字体，横向宽度测量与绘制使用相同配置。正文字体链为 `M PLUS Code Latin, .PingFang UI SC, system-ui`，代码字体链为 `M PLUS Code Latin, .PingFang UI SC, monospace`。macOS 中文显式保留当前苹方 UI 字形，避免拉丁字体的默认回退改用普通苹方；其他缺字继续由系统回退。字体注册不依赖用户机器安装，深浅主题颜色与字号、行距不随字体配置改写。来源与许可见 `internal/ui/fonts/README.md`，构建将许可复制到 bundle 的 `Contents/Resources/licenses/`。

## 删除会话

会话标签、左侧目录会话与右侧原生历史行统一通过右键菜单进入“删除会话”，菜单项使用完整名称。历史行整行用于打开会话，操作收在右键菜单中。确认框在 macOS 上将“取消”置于左侧、“删除会话”置于右侧；删除是确认操作，Escape 对应取消。确认内容明确说明删除标题、草稿、标签、历史展示范围及不可撤销性。关闭标签继续保留历史。

`internal/ui/session_delete.go` 在展示入口和确认完成时分别检查运行、恢复、历史加载、未确认发送、分叉、图片导入及退出状态；确认期间 ThreadID、Agent 或 Runtime 改变时保留会话并提示重试。原生历史尚未打开时可直接隐藏；确认期间已被打开的同身份会话使用当前状态重新核对。运行中的会话先完成或停止并核验，再执行删除。

删除从 Fuyu 的会话索引、草稿和标签移除记录，按 `Agent + Runtime + ThreadID` 保存隐藏标记。加载到的旧缓存、后续分页和重启后的原生列表均在呈现时过滤该标记。后台事件仍绑定原所属对象，已移除对象不再进入索引快照。Codex/Claude 的 CLI 原始历史、检查点、项目文件及可能被其他消息引用的图片副本保留；此入口不调用 Runtime 的全局停止或删除原生数据。

先通过 `Store.DeleteSession` 原子提交索引删除和设置快照，再更新界面。失败时保留会话和原标签、显示独立错误提示；删除当前标签后沿用相邻标签选择，删除最后一条会话创建新的空白会话，已选中的编辑文件及未保存内容保持原样。自动化的实际删除、取消、运行保护、失败回滚、重启与跨 Agent/Runtime 边界，以及原生菜单/确认/取消证据见[删除验证](../verification/2026-10-28-session-delete.md)。

## 图片消息与草稿

输入支持图片附件及纯图片发送，附件与文字、技能共用同一次 `turn/start`。`State.DraftImages` 与各会话草稿一起保存、恢复及分叉复制，发送前 `Begin` 将引用复制到用户消息；确定失败或提交结果不明时恢复附件供用户核验。当前后端不支持图片或附件文件不可用时，发送前显示具体错误。

原生历史将 `localImage` / `image` 投影为独立图片引用，文字保留原始内容。历史页中内联 data URL 在后台转换为应用副本后进入 UI，较早页同样处理；远程 URL 不自动下载，缺失图片显示不可用原因。资源与预览边界见[图片附件](attachments.md)。

## 初始等待提示

本轮请求尚未产生可见回复、工具或交互时，聊天区显示“正在思考”；实际可见输出、停止、错误或断线时按当前请求状态隐藏。文字通过单个 RichText 使用主题字体排版，逐字颜色变化呈现 1.8 秒扫光循环，避免额外叠画文字产生重影。系统启用减少动态效果时使用静态文字。验证见[思考提示验证](../verification/2026-10-27-thinking.md)。

## 会话列表的静默分页

会话历史同时读取默认 Codex 和已注册 Claude Code Runtime 的列表，每行标题前使用对应的 12 px Agent 图标，悬停显示来源及目录。当前项目/全部项目筛选和标题、路径搜索共同作用于合并列表；筛选按钮下不再重复显示项目名。打开、重命名及隐藏记录均按 Agent、Runtime 与原生 thread ID 定位，相同 ID 的不同来源独立保留。打开历史时按该行归属创建会话，模型及连接状态来自该 Agent。

合并目录是应用级共享的 `threadList`（`internal/ui/history.go`）：条目、各来源 cursor、分页与错误状态只属于应用，不属于任何会话。切换选中会话或项目只重新筛选，不清空也不重新请求；打开历史行不再按会话复制缓存，进行中的请求不因切换丢弃。没有来源字段的记录固定回落为默认 Codex 来源，不随所选会话改变归属。

各来源独立保存原生 cursor 和已加载状态，追加页按 Agent、Runtime、thread ID 去重，已结束及空列表不再重读。一种来源读取失败时保留另一来源成功取得的列表，并显示来源错误供重试；错误期间停止自动补页。完成的 Codex 或 Claude 会话在任务终态后，仅当其来源已被读取时插入共享列表并保持最新在前。

打开历史面板时（侧栏切换、“会话历史”页签或 `/resume`），未读取过的列表加载首页；已有列表只刷新各来源第一页：新会话按页顺序插到最前，已有条目原位更新标题与状态，分页 cursor 保持不变。刷新与分页共用单次在途互斥，冲突时保留一次后续刷新；请求期间已有列表照常显示。

右侧会话历史接近底部时自动读取下一页，筛选结果不足一屏时继续补页。正常请求期间保持已有列表，不渲染“正在加载…”文案；`threadList.loading` 继续保护单次在途请求，追加结果后等待测量再判断是否继续加载。错误时保留列表并提供具体错误与重试入口。验证见[历史加载验证](../verification/2026-10-27-history-loading.md)与[共享历史目录](../verification/2026-11-04-shared-history.md)。

## 模型选择

`internal/ui/models.go` 提供当前会话的单选菜单，列表来自 Codex `model/list` 分页结果，使用 `model` 字段提交而非目录项 ID，过滤隐藏项并按模型值去重。新会话及尚无模型选择的旧会话通过 `config/read(cwd)` 解析初始模型并保存为具体选择，菜单仅展示模型；异步结果固定所属会话且保留期间的手动选择；既有已选模型不在目录时仍显示当前选择。运行、恢复、占用及断线期间不能修改。列表读取失败提供重试，未知模型不作为新的可选推荐。

`storage.Session.SelectedModel` 在现有 JSON 记录中保存选择，无需 schema 版本变化；切换会话独立，分叉继承。选择持久化成功后关闭菜单，失败回退并保留错误。菜单底部的“运行详情”使用 24 DIP 次要文字行，左对齐文字、右侧进入箭头；详情将版本放在标题右侧，当前已提交模型使用浅底分组，审批和文件访问按两列对齐，底部提供轻量的重新加载入口；未知权限值保留原文，避免错误解释。

下一次发送捕获选择，统一 `SendWithModel` 发送文字、技能、图片及模型；修改模型不改变原生审批或沙箱。尚未完成初始化的会话发送前读取当前 cwd 的有效配置模型，未指定时使用模型目录默认项，并显式传入 `turn/start.model`，因为省略字段会沿用该 thread 上一次覆盖。解析失败发生在创建 thread/发送 turn 之前，保留草稿及附件、显示错误，不标为不确定提交。原生完成状态与消息仍按现有事件更新，UI 仅在提交成功后更新已用模型。

实际验证见[模型选择验证](../verification/2026-10-27-model-picker.md)。
