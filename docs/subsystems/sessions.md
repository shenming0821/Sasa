# 会话管理

## 会话与归属

`internal/ui/sessions.go` 的每个会话独立持有 `app.State`、列表与精确阅读偏移、草稿、工具展开、弹层和待核验标记。一个应用共享一个 Fuyu 自有 App Server，切换选中会话只切换视图，后台任务、审批和异步回调保持原归属。

`internal/ui/projects.go` 将已识别 Git 目录按仓库和 worktree 分组，点击工作区复用对应目录的已有会话，或创建独立新会话；每个工作区支持多个会话，所属 cwd 随新建固定。普通目录由 `internal/ui/navigation.go` 按完整路径分组，同名目录保持独立。项目扫描与异常边界见[项目管理](projects.md)。侧栏默认宽 240 DIP，可拖动调整至 200–320 DIP；搜索标题与完整路径，搜索期间展开匹配的项目，清空搜索后恢复折叠状态。会话显示稳定标题、运行/失败状态和待办数量。顶部标签显示已打开的会话，保存打开列表并在重启后恢复，横向滚动，选中项切换时滚入可见区域；新会话和项目导航均使用已有会话归属逻辑。每个标签右侧提供独立关闭按钮，关闭后保留侧栏记录、草稿、阅读位置、工具状态与后台任务；重新点击项目会话或原生历史可打开。关闭当前标签时优先切换左邻已打开标签，再选右邻；关闭最后一个标签时显示空白主窗口，不创建新会话；保留侧栏和新建入口，历史与后台任务继续保留。已加载会话在本进程内保留状态，重开无需重复恢复；关闭期间恢复回调仅更新原会话，不重新打开标签或抢占当前选择。

工具栏显示当前目录，运行详情显示原生返回的模型、审批策略和沙箱值。已有任务选择另一个目录时新建会话；空白会话直接设置 cwd。常规启动恢复上次选中项与已打开标签；显式启动参数 cwd 不同时按原有目录选择规则打开对应会话，保留其他已恢复标签，避免同目录的另一个会话抢占。

右侧历史默认收起，展开后始终作为窗口内部的侧栏，与中间会话并排。文件、会话历史和 Git 共用右侧宽度，默认 320 DIP，可拖动与主窗口之间的分隔线调整至 240–520 DIP；分隔线的悬停、拖动与键盘方向键反馈复用左侧的 MyGo Split。空间允许时为中间会话保留至少 400 DIP，640 DIP 窗口下右侧保持最小 240 DIP。窄窗口临时缩小右侧，不覆盖用户的首选宽度，窗口变宽后恢复。支持当前目录/全部项目筛选与已加载标题/路径搜索；分页继续使用原生 cursor，搜索范围明确限于已加载记录。打开已有 thread 时切换对应本地会话，历史侧栏保持展开。

窗口不足以同时放下左侧项目、历史和 400 DIP 会话区域时，优先收起左侧项目；工具栏可临时展开项目导航，选择会话后项目面板收起。历史侧栏随用户开关保持显示，不覆盖消息和输入区。主动开关、侧栏宽度和项目折叠偏好存入现有 JSON 设置，旧数据库缺失字段使用默认值，无须 SQL 迁移。

主聊天区顶栏显示工作目录与侧栏切换入口，所有会话阶段文字（包括就绪、执行中及本轮完成）统一从该位置移除；内部状态、侧栏状态与任务操作继续沿用原有机制。

每侧保留一个切换按钮，提示和无障碍名称分别为“切换左侧边栏”和“切换右侧边栏”。侧栏展开时按钮位于对应侧栏顶部，右侧同样使用侧栏图标；侧栏收起时按钮移到主聊天区顶栏。窄窗口临时项目面板遵循相同规则。

`forSession` 只绑定所属会话、传输和主线程派发资源。`thread/start` 成功后，先在主线程登记原生 ID 并保存索引，成功后再发 `turn/start`。后台回调通过 `Window.Update` 更新所属会话。共享断线向全部会话传播；普通事件按原生 thread ID 过滤。

## 历史恢复

应用索引的持久 ID 和界面状态见[存储与恢复](storage.md)。消息和工具正文来自 Codex 原生记录：

1. 启动只读取索引元数据，恢复保存的打开标签和选中项；只为选中会话请求原生历史，其他已打开标签在首次点击时恢复。关闭的会话保留在项目侧栏，点击时重新打开。旧记录缺少打开列表时，仅打开选中项；不存在的标签 ID 忽略，选中项失效时回退到有效已打开标签。未加载会话保留草稿和历史状态，不批量请求 `thread/resume`。未确认任务显示“上次任务待核验”，发送在实际核验前保持关闭。
2. `thread/resume(excludeTurns=true)` 获取实际目录、模型、审批策略、沙箱和原生状态。
3. `thread/turns/list(itemsView=full, sortDirection=desc, limit=20)` 加载最新页，反转为时间顺序投影。向上滚动到接近顶部时，按原生不透明 cursor 自动加载更早页，以 item ID 去重并保持当前阅读位置；主窗口不显示手动加载按钮。内容不足一屏时继续补页；加载失败后保留已有历史与错误提示，离开顶部再返回可重试。
4. 最新状态明确 idle、turn 有确定终态且不存在未确认提交时，允许在相同 thread 继续新 turn。原生 active、未结束 turn、未知状态和恢复失败保留待核验。

`internal/app/history.go` 重建用户消息、回复及结构化工具，复用现有状态投影。旧 stdio 请求不序列化，旧审批和表单不会重新生效。原 thread 未取得 ID 时不自动重发，用户先浏览原生历史，再显式确认继续。

恢复期间按会话暂存最多 2 MiB / 1024 条事件。快照可能已含缓冲增量，不能再拼接 delta；保留控制事件，对增量缺口重新核验权威条目。缓存溢出保留待核验，不静默显示完整。

### 被其他应用占用

当原生 `thread/resume` 返回对应 thread 的 `-32600: thread <id> already has an active writer` 时，将该会话标为外部占用。通过 `thread/read(includeTurns=false)` 读取元信息，再用现有分页接口加载只读历史。其他错误保持原有恢复失败语义；历史读取失败时保留占用卡和已有消息，显示具体读取错误。

底部使用锁图标、“已在另一个应用中打开”和“请先在那边关闭会话，才能在这里继续。”提示卡，替代输入框和通用恢复入口。“重试”重新核验原会话；占用释放且原生任务终态明确后恢复输入。重试期间保留提示卡，两个操作禁止重复触发。占用状态不会将外部任务变为 Fuyu 的 Busy、审批或退出中断目标；相关事件不会授予写入控制。

“创建聊天分叉”调用 `thread/fork(excludeTurns=true, deferGoalContinuation=true)`，建立独立原生 ID 和本地会话，立即保存索引，再分页加载返回会话的历史。直接使用 fork 返回的状态与配置，保留目标延后续跑状态，等待用户显式发送任务。原会话和草稿保留，草稿同时复制到分叉；异步完成时仅在用户仍查看原会话的情况下切换到新标签。失败保留原会话；连接丢失等结果不确定时暂停重复创建，提示从原生历史核验。

外部占用由每次恢复重新核验，不单独持久化。保存占用视图时保留已有的本地未确认提交标记，避免仅因外部占用而制造新的提交不确定性；阅读位置与工具展开仍按现有方式保存。

更早页加载保持当前 turn、Busy、草稿和新消息；显示仍受 1000 条 / 8 MiB 限制。到达边界时停止加载并显示原因，原生记录继续保留。

## 阅读与界面恢复

正常恢复历史后直接显示对话；需要核验旧任务、恢复失败或阅读位置异常时显示对应提示。

保存首个可见原生 item ID、条目内相对偏移和是否跟随末尾。恢复锚点位于旧页时自动向前分页，找到后使用稳定 Handle 恢复长回复内部的精确位置；找不到或达到显示上限时明确说明边界。已加载条目的工具展开状态更新索引，尚未加载条目的旧值继续保留。

标题优先使用已保存摘要，避免分页窗口变化后标题随首条可见用户消息改变。草稿和选中会话、侧栏开关均从索引恢复。

输入候选位于 `internal/ui/completion.go`。`/new`、`/resume`、`/status`、`/skills` 执行本地已有动作；`$` 按当前 cwd 请求原生技能，支持筛选、键盘和鼠标选择，输入法组合期间暂停候选确认。候选浮层不取得输入焦点；选中技能只替换光标前 token，并继续编辑。技能缓存与选择归属会话，选择的名称/路径随草稿保存；发送仅附带仍在草稿中的引用。详见[输入候选验收](../verification/2026-10-23-input-completion.md)。

## 关闭与退出

`internal/ui/lifecycle.go` 在关闭窗口时保存并隐藏；Fuyu 与后台任务继续运行。Dock 的“打开 Fuyu”或再次激活应用显示原窗口。

退出时先保存；有活动任务时列出所有受影响会话和目录。选择“停止任务并退出”后，逐个发送中断并等待原生终态，等待期间禁止新发送。10 秒后仍未确认时提供“返回核验”与“强制退出”。连接丢失保留不确定性，不能当作停止终态。强制退出前保存未确认任务标记，重开后继续核验。

结束应用关闭自有 App Server 并清理原进程组；独立进程组的后台后代不在当前保证范围。历史恢复不代表重新附着旧 stdio 执行。

## 工具记录呈现

`internal/ui/tool_details.go` 为 MCP、动态工具和网页搜索提供默认折叠的单行记录。优先读取输入的 `title` 作为动作说明，缺少时显示工具名称；点击整行或键盘操作展开与收起，复用原工具的 `Expanded` 状态与既有索引恢复。命令组与工具记录共用 `processDisclosure`：30 DIP 行高，左侧 16 DIP 图标和标题同级对齐，命令使用带短横线的终端窗口图标，工具使用四方块图标；箭头位于标题右侧，悬停或键盘聚焦时显现，复用 MyGo 的展开动画、键盘及减少动态效果行为。过程标题、耗时、状态与详情统一使用灰色次要文字，命令标题使用常规字重。运行中显示进度和实际状态，成功时只保留耗时，失败/拒绝通过状态文字说明；失败折叠态保留两行错误摘要。命令组与未成功的文件修改继续使用各自现有呈现。

展开内容以轻边框浅色背景区分，包含工具名、输入和结果。带 `code` 的输入将代码单独显示，其余参数保留（标题已用于动作说明）；每块可复制。输入代码横向滚动，普通结果自动换行，每块纵向最大 280 DIP，长内容内部滚动。

结果只展开已识别的 `content`/`text` 文本包装，最多递归十六层；文本中的 JSON 字符串按结构解码换行和制表符。附加字段保留在解码内容之后，非文本块、格式错误或截断数据保留原文/JSON，避免丢失信息。`isError` 返回保持错误状态；展示格式化不改写协议原始消息。截断始终可见。连续工具调用本轮仍分别展示。聊天列表由 `conversationSpacing` 按相邻行类型确定留白：相邻命令组/工具记录之间为 4 DIP，正文、过程记录及文件变更卡片之间为 12 DIP，用户消息前后为 24 DIP；首行不添加额外留白。正文与复制按钮间为 4 DIP，复制按钮为 24 DIP。虚拟列表使用实际行高测量，稳定消息 ID 与阅读锚点机制保持不变。

验证见[工具记录验证](../verification/2026-10-27-tool-details.md)。

聊天 Markdown 的无序列表标记列最多 1.4 em（当前字号 15 DIP，对应 21 DIP），圆点与正文更紧凑，嵌套层级及换行缩进沿用原渲染。有序列表保留 3 em 编号兼容宽度，流式与完成态使用相同设置。实现见 `scripts/mygo-input-style.py`，编号和无序列表回归见 `internal/ui/app_test.go`。

页签标题悬停仅显示一次完整标题，不追加工作区或文件完整路径；会话、文件和 Diff 页签关闭按钮保留无障碍名称与点击行为，悬停时不显示气泡。标题和关闭入口使用透明的 `ButtonBase`，悬停时保持背景不变；选中页签底色、底边标记及键盘焦点提示继续保留。验证见 `TestTabTooltipsShowOnlyTitleAndSkipClose`。

会话历史列表分页按原生 thread ID 合并：同一页及跨页重复项更新已有条目的元信息并保持位置，不同 ID 的同名会话分别保留。请求期间避免重复加载，已有列表且分页游标为空时停止请求，防止再次从第一页追加。受控回归见 `TestThreadHistoryMergesPagesByIDAndStopsAtEnd`。

会话历史使用滚动分页：距离底部 80 DIP 内自动加载下一页；筛选结果不足一屏时继续补页，新增记录布局完成后再判断下一次加载。移除“加载更多会话”按钮，加载时显示次要文字，失败保留已加载内容并提供“重试”，避免自动循环重试。分页追加保留当前滚动位置。

### 用户提问排版

用户消息使用可选择的原生纯文本，字号 15 DIP、字重 400、行高 1.6 倍（24 DIP），气泡上下内边距 16 DIP、左右 20 DIP；沿用统一中英文字体配置、主题文字颜色与底色，最大宽度为阅读列的 85%，右对齐。原始换行、编号、路径与消息内容保持原样，长连续英文自动换行；不将用户输入解释为 Markdown。

### 默认中英文字体

`internal/ui/fonts.go` 嵌入并注册未修改的 `M PLUS Code Latin` 可变字体，统一窗口主题与 Markdown 正文默认字体；代码、命令、编辑器、冲突与 Diff 使用同款拉丁字体，横向宽度测量与绘制使用相同配置。正文字体链为 `M PLUS Code Latin, .PingFang UI SC, system-ui`，代码字体链为 `M PLUS Code Latin, .PingFang UI SC, monospace`。macOS 中文显式保留当前苹方 UI 字形，避免拉丁字体的默认回退改用普通苹方；其他缺字继续由系统回退。字体注册不依赖用户机器安装，深浅主题颜色与字号、行距不随字体配置改写。来源与许可见 `internal/ui/fonts/README.md`，构建将许可复制到 bundle 的 `Contents/Resources/licenses/`。

## 图片消息与草稿

输入支持图片附件及纯图片发送，附件与文字、技能共用同一次 `turn/start`。`State.DraftImages` 与各会话草稿一起保存、恢复及分叉复制，发送前 `Begin` 将引用复制到用户消息；确定失败或提交结果不明时恢复附件供用户核验。当前后端不支持图片或附件文件不可用时，发送前显示具体错误。

原生历史将 `localImage` / `image` 投影为独立图片引用，文字保留原始内容。历史页中内联 data URL 在后台转换为应用副本后进入 UI，较早页同样处理；远程 URL 不自动下载，缺失图片显示不可用原因。资源与预览边界见[图片附件](attachments.md)。

## 初始等待提示

本轮请求尚未产生可见回复、工具或交互时，聊天区显示“正在思考”；实际可见输出、停止、错误或断线时按当前请求状态隐藏。文字通过单个 RichText 使用主题字体排版，逐字颜色变化呈现 1.8 秒扫光循环，避免额外叠画文字产生重影。系统启用减少动态效果时使用静态文字。验证见[思考提示验证](../verification/2026-10-27-thinking.md)。

## 会话列表的静默分页

右侧会话历史接近底部时自动读取下一页，筛选结果不足一屏时继续补页。正常请求期间保持已有列表，不渲染“正在加载…”文案；`threadsLoading` 继续保护单次在途请求，追加结果后等待测量再判断是否继续加载。错误时保留列表并提供具体错误与重试入口。验证见[历史加载验证](../verification/2026-10-27-history-loading.md)。
