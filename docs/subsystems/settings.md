# 设置与完成通知

## 已实现范围

设置入口位于左侧栏标题的齿轮按钮，同时支持应用菜单“设置…”和 Cmd+,。浮层分为“通用”“外观”“通知”，首次打开显示通用，之后保留本次运行选择的分类。Escape、关闭按钮及 Cmd+W 关闭设置并保留当前会话；原生关闭窗口时优先收起设置。

外观包含跟随系统/浅色/深色、英文字体、中文字体和代码字体。初始英文字体与代码字体均为 M PLUS Code Latin，中文为现有系统中文 UI 字体。字体列表来自本机与应用注册字体，支持搜索并勾选当前选择，中英文与代码预览同步更新。英文与代码字体分别控制普通内容、代码块/命令/编辑器/Diff；两者共用所选中文回退。主题及字体的标签与控件同行，标签列固定 64 DIP，控件共用对齐边界；字体浮层宽度与触发控件一致，搜索框和列表填满内部可用宽度，长名称单行收缩。字号、密度及发送行为继续使用现有值。

## 状态与保存

字体菜单始终保留该类别的默认值和当前值，即使系统字体枚举不包含该名称，切换后仍可恢复。中文的“系统中文字体（默认）”对应 `.PingFang UI SC`，与普通字体列表中的 `PingFang SC` 分别保存；英文和代码默认值为 `M PLUS Code Latin`。这些设置用于 Fuyu 界面、编辑器和消息，原生终端继续使用 Ghostty 自身的字体配置。

`storage.Snapshot.Preferences` 保存应用级设置，复用 SQLite settings JSON，不新增数据库版本。旧快照没有 Preferences 时采用默认值：主题 system、保持唤醒 never（永不）、后台完成通知开启、通知声音关闭。选项修改立即持久化，保存失败恢复旧值及保持唤醒策略，并在页面显示错误。保持唤醒切换时先核验系统调用，失败保留原设置；字体名称不可用时由字体回退链处理，字体列表随应用重启刷新。

运行时主题通过 MyGo ThemeSource 设置，跟随系统时保留系统强调色和无障碍偏好；组件测试使用对应主题模拟。Markdown 与显式代码字体共用同一设置源。代码或中文字体变化时取消旧测量、清空已打开文件的宽度缓存，使用同一字体重新测量编辑器与 Diff 横向范围，旧字体异步结果不得覆盖当前宽度。

## 通用：辅助模型与自动会话标题

“辅助模型”从当前已连接的 Claude Code 配置读取模型列表，仅暴露「模型」一个下拉。首选 Claude backend 在连接时自动写入 `Preferences.AuxiliaryRuntime`；`AuxiliaryModel`、`AuxiliaryModelName` 保存具体模型选择，不影响聊天模型或上次使用的模型。模型下拉复用主窗口菜单结构：头部一行「选择模型」加右侧刷新按钮（加载时显示 spinner），列表项右侧 `✓` 与刷新图标同列对齐；错误、加载中和空态提示显示在菜单底部，不占用设置页空间。

“自动生成会话标题”保存于 `Preferences.AutoSessionTitle`，默认关闭；开启前必须选择可用模型（开关仍可点击，未选模型时回滚并在设置页提示）。关闭后取消待执行的自动任务，正在执行的自动结果失效，已有标题保留。重新开启后从后续完成的问答开始，不补扫历史。保存失败恢复原设置。

自动标题同时用于 Codex、Claude 会话。首次完整问答结束并空闲 60 秒后生成；后续必须同时满足距上次检查至少 30 分钟、新增至少 5 轮完整问答，再等待会话空闲 2 分钟。输入或发送重置本会话空闲计时；其他会话运行不阻塞已经空闲的会话。无新内容不调用，保留原标题的成功检查也消耗本批内容的检查额度；失败不立即重试，等待后续问答达到相同门槛。

会话右键“重新自动生成标题”跳过时间和轮数门槛，开关关闭时仍可使用；成功后清除手动标题，恢复自动管理资格。手动重命名锁定标题，自动任务不覆盖。关闭的历史会话可只读获取最近正文并生成标题，不切换当前会话或恢复任务。显示、搜索及重启恢复共用 `CustomTitle → AutoTitle → 原标题` 优先级。

后台任务复用既有维护循环，全应用最多同时执行 1 个标题请求，手动请求优先，用户聊天发送准备优先启动。单次输入最多取 6000 个正文字符，保留首个问题与最近问答，排除草稿、附件、工具记录及围栏代码块，单条正文最多 1000 字。输出为最多 28 字的单行标题，单次调用超时 90 秒。Claude 使用临时目录、独立系统提示词、空工具集、禁用技能及 hooks、空 MCP 配置和不保存会话的运行方式；每次结束立即回收进程。标题请求不进入聊天记录、历史列表、未读和完成通知。改名、删除、切换模型、新任务或关闭开关使相应旧结果失效。

实现见 `internal/ui/session_titles.go`、`settings_auxiliary.go` 和 `internal/claude/auxiliary.go`。

## 通用：保持 Mac 唤醒

“让这台 Mac 保持唤醒状态”的标题与下拉框同行排列，下方一行备注说明写入系统电源设置、需要管理员授权且退出后仍生效。下拉选项：永不 `never`、始终 `always`、仅使用电源适配器时 `ac-only`。默认永不；旧快照缺失或未知值归一到永不。

`internal/power/` 直接读写 macOS `pmset` 电源配置，与系统设置及其他软件（如“仅使用电源适配器时”）共用同一状态，不再是 Fuyu 私有的运行时断言。读取使用 `pmset -g custom` 解析 AC/电池两个 profile 的 `sleep` 值，无需权限；写入通过 `osascript ... with administrator privileges` 执行 `pmset -c/-b sleep`，每次修改弹系统密码授权框，授权取消或失败时保留原选择并显示错误。

档位与系统值的对应：AC=0 且电池=0 → 始终；AC=0 且电池>0 → 仅使用电源适配器时；其余 → 永不；不归入三档的组合就近归类（电池=0 且 AC>0 归为永不；台式机无电池 profile 时只看 AC）。应用启动与每次打开设置页执行 `Sync` 读取系统状态，显示值始终反映实际系统配置，其他软件修改会在下次打开时同步进 Fuyu。

`Set` 写入前先读当前值，目标与现状一致时不写、不弹授权。Fuyu 首次写入前把当时系统值记入 `Preferences.KeepAwakeBaseline`（JSON 持久化，重启后经 `RestoreBaseline` 恢复）；“永不”恢复两档正数计时，“仅接电”写 AC=0 并恢复电池的正数计时，“始终”写两档为 0。恢复时优先使用基线正数；基线为 0 或无有效值时使用 10 分钟，确保允许睡眠的档位实际生效。基线只记录一次，其他软件后续修改不会改变还原目标。`PendingBaseline` 在保存成功前持续提供基线，保存成功后才调用 `ConfirmBaseline`，保存失败、回滚及重试均保留原值。

UI 在后台执行授权、系统写入和保存失败后的回滚，通过主线程回写选择及错误。等待期间保留原选择，拦截重复电源修改，其他偏好可继续编辑，异步结果仅更新电源相关字段；重新打开设置时跳过与写入竞争的同步读取。退出时要求先完成或取消正在进行的电源授权。Controller 通过独立操作锁串行化读写，状态锁不覆盖进程调用；错误读取不会等待授权。读取命令限时 5 秒，授权写入限时 2 分钟，关闭 Controller 取消授权进程；AC/电池分别使用独立 `pmset` 命令，并在写入后读取核对目标值。

屏幕熄灭、合盖与手动睡眠仍由系统规则决定，本设置只控制闲置睡眠的 `sleep` 值，不触碰 `displaysleep`、`disablesleep` 等其他键。自动化覆盖解析、零值与正数基线的档位往返、无变化跳过写入、失败保留、保存重试、授权等待时的交互与并发。

## 任务完成通知

仅在真实事件链中接收到本会话从 Busy 转为空闲的 `turn/completed` 且状态 completed 时考虑通知。窗口在后台、当前显示其他标签或设置页时提醒；正在查看当前会话时保持安静。中断、失败、恢复历史、断线和重复终态不发完成通知；退出流程也不提醒。

通知使用 MyGo 系统通知，按会话替换和分组，文案为“任务已完成”及会话标题；系统通知正文不包含回复正文。提示音由通知 Silent 控制，仅对开启的完成通知生效。点击通知打开对应会话。系统不支持或权限拒绝时在通知设置显示错误，不阻断会话。

本轮不含字号、内容密度、发送方式、默认模型、Diff 行为及待处理事项通知设置。
