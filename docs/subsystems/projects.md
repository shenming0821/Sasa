# 项目与工作区管理

## 范围与入口

左侧按“仓库 → Git worktree / 分支 → 会话”显示。“项目”标题右侧提供“添加项目”和“刷新”两个图标按钮。“添加项目”统一选择本地文件夹：有 Git 信息时自动发现整个仓库的全部已登记 worktree，包括主目录、关联分支目录及 detached 工作区；从任一关联工作区添加都按 common dir 去重。没有 Git 信息的文件夹按普通目录项目添加，导入后在该目录的 workspace 打开空白新标签页由用户挑选 Codex / Claude / 终端，复用已有空白标签；不主动创建绑定具体 agent 的会话。导入和刷新只读取现有工作区。Git 配置损坏、权限及扫描失败继续显示错误，保留已有列表。

也可从 Finder 等外部应用将文件夹拖入左侧“项目列表”的空白区域或列表条目。悬停时由 `internal/ui/sidebar_drop.go` 使用 DrawOver 绘制 Accent 内描边及“拖入文件夹以添加项目”提示，不占布局或增加交互节点。投放后先占用项目导入忙碌状态，再在后台按路径顺序筛选第一个目录，复用 `internal/ui/projects.go` 的导入流程；多目录仅添加第一个，全是文件或无有效目录时显示错误。导入或刷新进行中忽略新的投放。Git 项目导入保留当前会话，普通目录沿用添加项目时打开空白新标签页的行为。外部投放不触发底层条目的点击、折叠或项目排序；窗口内项目与页签拖拽继续使用各自的通道。受控测试见 `internal/ui/sidebar_drop_test.go`，覆盖 Codex 与 Claude。

## 新建 Worktree

Git 仓库总标题的右键菜单提供“新建 Worktree”。弹窗包含可搜索的基础分支、新分支名和文件夹名称。来源包括本地分支及已获取的远程分支，不自动 fetch；默认取本仓库当前选中工作区的分支，否则取主工作区分支，detached HEAD 显示“当前提交”和短哈希；尚无提交时提示先完成首次提交。

文件夹名称默认跟随分支名，将 `/` 转为 `-`；用户编辑后保持自定义名称，清空后恢复跟随。仅接受单层名称，拒绝空名称、`.`、`..`、路径分隔符、冒号和控制字符。存放位置实时预览并支持复制完整路径。位置统一为当前应用数据目录下 `worktrees/<规范化 common dir 的 SHA-256 前 24 位十六进制>/<文件夹名称>`，目标路径存在时提示修改名称。

基础分支选择器使用原生虚拟列表，只构建可见行和少量预读行；搜索结果按查询变化缓存，输入新查询时滚动回首项。全部分支保持可搜索、可滚动访问，不裁剪候选数量。选择器与 Git 面板统一使用 `internal/ui/git_branches.go` 的仓库级分支缓存，复用完整本地和远程引用；弹窗不再单独枚举分支。

分支缓存以规范化 Git common dir 为身份，Git 面板已有缓存优先复用，同一仓库多个工作区及弹窗的同时请求合并为一次读取。项目尚未发现时先按工作区根目录缓存，发现仓库后将已有缓存接续到 common dir。有效缓存立即显示，超过 30 秒在后台更新；刷新结果中候选没有变化时保留搜索结果与滚动位置。Git 面板继续仅显示本地分支，创建弹窗显示本地和远程分支；当前分支、文件状态及暂存仍属于各工作区，不能复用另一工作区的当前标记。

Git 面板正常状态刷新复用分支缓存；手动“刷新 Git”、分支或远程操作、新建 worktree 及 Git 引用元数据变化使缓存失效。普通文件和 index 变化只刷新工作区状态。分支读取进行中再次失效时丢弃旧结果，完成后统一补读；失败保留可用缓存和用户输入，并支持重试。实际创建及切换仍按原 Git 操作重新校验。共享缓存只在内存中维护，未增加持久化字段。

`internal/git/worktree.go` 在后台重新校验分支、目录和来源，解析到提交后使用 `git worktree add -b` 创建。操作过滤继承的 Git 目录和 index 覆盖变量；原工作区的当前分支、暂存及文件保持原状，新目录仅包含所选提交，不复制未跟踪文件或安装依赖。创建期间防止重复提交，关闭弹窗和正常退出等待 Git 写入完成。失败或超时后独立核对目录、分支和登记状态并保留残留内容，登记存在本身不作为检出完整成功的依据。

创建成功后重新发现仓库、展开并选中新目录，进入该目录的面板内容选择入口；首次发送再启动实际任务。若创建成功但刷新失败，保留实际路径并提供“重试刷新”，该动作仅重试发现。重启沿用现有仓库扫描，无额外持久化表。首版不提供已有分支创建、删除、归档或自动清理。

`internal/project/repository.go` 只读执行 `git -C <path> rev-parse --git-common-dir` 和 `git -C <path> worktree list --porcelain -z`，规范化公共 Git 目录作为仓库身份。列表使用 NUL 分隔，保留中文、空格、换行路径；主工作区按 Git 列表首项标识。branch、HEAD、detached、bare、locked、prunable 各自解析，目录存在性在后台扫描时核验。扫描使用当前机器可执行的 Git；调用错误原样保留上下文，不将失败当作成功的空列表。

## 导航与会话

普通目录项目名称的右键菜单提供“在Finder中打开”和“移除项目”；Git 仓库下各 worktree 文件夹卡片的右键菜单提供“在Finder中打开”和“重命名”，Finder 使用所点击卡片对应的实际目录，保留自定义显示名称。仓库总标题继续提供“移除项目”。打开前核验路径仍为目录，缺失、路径类型变化或系统打开失败时使用现有错误弹窗显示路径和原因。移除项目仅隐藏 Fuyu 项目列表入口，实际文件和历史会话保留。

工作区卡片第三行的会话摘要前显示该会话对应的 12 DIP Agent 图标，复用会话标签和历史列表的 Codex/Claude Code 图标及配色，图标与标题间距为 6 DIP。图标跟随实际显示的摘要会话，搜索切换匹配摘要时同步更新；无会话摘要时保持两行卡片。

普通目录项目展开后的各会话标题前同样显示对应的 12 DIP Agent 图标，与标题间距为 6 DIP；标题继续单行截断，Agent 通过图标识别，有会话状态时在标题下方显示状态。会话行保留点击切换和右键菜单，悬停时保持标题可见，移除显示内部会话编号的气泡提示。

`internal/ui/projects.go` 负责异步导入、扫描与仓库行。仓库名加粗，工作区显示目录短名与分支；主要工作区带“主要”标记。点击工作区时恢复该文件夹上次选中的打开页签；当该文件夹没有打开页签时，显示面板内容选择入口（Codex、Claude Code、终端），不再自动创建会话。已关闭会话保留历史与草稿，用户通过历史入口主动重开。工作区卡片只保留目录点击入口，没有右侧新建按钮；在当前工作区另开会话时使用顶部新建入口，一个工作区可有多个会话。左侧仅在工作区下显示已有对话、原生历史或未确认任务，空白与仅有未发送草稿的会话不额外显示“新会话”占位行。隐藏的空白会话保留标签和草稿，点击工作区仍可进入；首次发送任务后显示对应会话行。当前选中的是隐藏空白会话时，工作区行承担选中态。工作区名称、分支和最新已有对话合成一个圆角列表项，由外层卡片统一绘制选中与悬停背景，覆盖整张卡片。透明主按钮占满卡片宽度，右侧边缘也可点击进入工作区，键盘聚焦保留可见反馈；分支工作区名称与上方仓库名称的文字起点对齐（卡片左内边距 29 DIP，对应标题 8 DIP 内边距、14 DIP 图标和 7 DIP 间距），分支信息、会话摘要沿用同一文字起点。文字层级按 Orca 参考：仓库标题 14 DIP 加粗深色，工作区名 13 DIP 深色常规字重，会话摘要 11 DIP 次要灰色常规字重，分支与状态 10 DIP 次要灰色，“主要”为 9 DIP 细边标签。空白会话不替换已有对话摘要，其他会话继续通过标签和历史入口进入；搜索时显示最新匹配的对话。卡片不展示其他应用占用会话的提示，该状态在打开对话后显示；运行、失败及待处理状态继续保留。

会话依旧以绝对 cwd 绑定，Git 分支只是可刷新的显示元数据；外部切换分支不重写已有 thread 的目录或创建新 thread。子目录会话归到包含它的最深已导入 worktree，避免嵌套仓库归属冲突。关闭标签、草稿、活动任务、历史和重启标签恢复沿用原会话机制。导入和扫描不创建 Codex thread 或发送模型任务。

仓库、分支工作区及普通目录标题行均不显示路径或动作气泡，目录标题不显示会话数量。项目标题使用全宽按钮，展开/收起箭头位于右侧，在整行悬停或标题键盘聚焦时显示，隐藏时保留占位以避免文字跳动；点击整行展开/收起，项目操作通过标题右键菜单进入。标题与箭头共用整行圆角悬停背景。目录标题及会话条目在鼠标按下期间沿用悬停底色，不额外加深；当前选中项仍保留选中态。展开和收起使用 200 毫秒高度裁剪过渡，右侧箭头随进度旋转；收起结束前保留内容以连续过渡，系统开启“减少动态效果”时直接切换。

搜索支持仓库名、路径、分支与会话标题；匹配会话会显示其工作区和仓库层级。折叠使用现有 `CollapsedProjects`，仓库以 common dir 为 key，普通目录继续使用路径。

## 按文件夹展示页签

顶部页签栏只展示当前文件夹的会话、文件、Diff 和终端；同一仓库的每个 worktree 独立分组，worktree 子目录会话归入最深匹配的 worktree。普通目录按各自路径分组，未绑定目录的既有会话保留独立分组且不生成侧栏目录入口。底层保留全部打开页签，切换分组保留后台任务、草稿、编辑状态和终端 shell。

点击 worktree 卡片恢复该文件夹上次选中的页签，记录失效时进入同组首个有效页签；没有打开页签时进入面板内容选择入口。普通目录标题继续只控制展开/收起，点击具体会话或历史记录直接进入指定会话。关闭当前页签后优先选择同组前一页，再选择后一页；关闭同组最后一页后保留当前文件夹的空工作区，Cmd+W 不影响其他文件夹的页签。

worktree 名称和普通目录标题保持加入绿点前的文字起点；绿点绝对定位在左侧既有缩进中，普通目录的文件夹图标保持原位。当存在打开页签时显示主题成功色的 6 DIP 绿点；空闲会话、文件、Diff 和终端均计入，最后一页关闭后隐藏，名称与可用文字宽度保持稳定。辅助功能说明为“有打开的页签”。仓库总标题保留现有外观。实现由 `internal/ui/folder_tabs.go` 统一管理归属、记忆和关闭回退；恢复及持久化见[存储与恢复](storage.md)。

## Worktree 显示名称

工作区卡片（含主工作区）右键提供“重命名”，在弹窗中编辑显示名称，点击“保存名称”或按 Enter 保存。输入两端空白会被清理；留空或填写原文件夹名称恢复默认。取消、Escape、Command+W 或点击弹窗外侧放弃本次编辑；保存失败保留旧标题及输入内容，显示错误供重试。

`internal/ui/worktree_rename.go` 管理显示名称与编辑弹窗。名称按发现的绝对 worktree 路径保存在 `storage.Snapshot.WorktreeNames`，通过既有 settings JSON 持久化，数据库 schema 保持当前版本。主工作区和关联 worktree 均可独立命名，允许同名；刷新 Git 元数据与重启应用保留名称。移除项目后重新添加相同路径仍使用原名称；外部移动工作区后，新路径使用默认文件夹名称。

名称仅替换项目列表工作区卡片的首行标题，分支标签、仓库标题、磁盘目录、Git worktree 登记和会话 cwd 保持原身份。搜索同时匹配显示名称、路径、分支和会话标题；右键编辑入口继续绑定路径。

## 项目排序与移除

`internal/ui/project_order.go` 合并仓库和普通目录为同一项目列表。侧栏项目列表仅收录有工作目录的会话；未绑定目录的会话不生成“未选择项目”分组，既有记录、草稿和打开的标签继续保留。拖拽标题到另一标题的上半部或下半部，在插入线处松开即可放到前面或后面；Escape 取消拖拽，普通点击继续控制折叠。仓库标题右键提供“新建 Worktree”和“移除项目”，普通目录标题提供“在Finder中打开”和“移除项目”；项目排序通过拖拽标题完成。

顺序以 `repo:<common dir>` 和 `dir:<cwd>` 为稳定标识保存；搜索只过滤呈现，移动使用完整项目列表。重新导入已有可见项目保持位置，新项目或移除后重新添加的项目放到末尾。普通目录在后台识别为仓库时继承已保存的位置。

“移除项目”从侧栏移除整个项目及下属工作区，保留磁盘目录、Git worktree、会话、草稿、标签和当前任务。仓库元数据继续保留以维持会话归属，避免会话重新出现在普通目录分组。`HiddenProjects` 随索引保存；启动与周期刷新跳过已移除项，扫描过程中发生的移除也在主线程合并结果时保留。用户通过“添加项目”显式恢复；普通目录沿用原会话和草稿。

## 刷新、持久化与异常

启动、手动点击“刷新项目”以及每 30 秒触发一次扫描。整个刷新最多 20 秒，导入最多 10 秒；同一时刻只有一个项目扫描。耗时 Git 与文件状态读取在后台执行，结果通过主线程更新并持久化；应用退出会取消扫描上下文。

先刷新已保存仓库；主目录无法扫描时尝试关联 worktree。扫描成功且 common dir 相同才替换缓存，失败保留上次列表并显示“刷新失败，保留上次列表”，提示中保留具体错误。现有会话的尚未识别目录也在后台尝试发现，普通目录不报 Git 错误。外部删除 worktree 后，相关会话和草稿仍保留，必要时回到普通目录分组。

目录树和搜索结果隐藏 prunable 登记与实际缺失目录，保留底层缓存及原会话以便恢复；扫描失败继续保留上次列表和错误，不主动清理 Git。bare 仓库本身不能新建工作区会话；locked 只是 Git 管理锁，仍可在存在的目录中对话。工作区导入通过 common dir 去重，符号链接导入也归一化身份。项目移除通过下述侧栏菜单提供；Git 分支与工作区操作见 [文件、编辑器与 Git](editor.md)。

`storage.Snapshot.Repositories`、`ProjectOrder`、`HiddenProjects` 使用现有 settings JSON，本轮保持当前数据库 schema 3。缓存包含工作区状态，不包含消息正文或凭据。重启先显示缓存，后台刷新元数据；只有选中会话按现有机制加载原生历史。
