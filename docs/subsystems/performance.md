# 使用性能与后台维护

## 窗口启动与模型目录

窗口在读取本地应用索引后创建，Codex 路径发现、版本探测和 App Server 初始化移到窗口创建后的后台执行。恢复子进程 PATH 后，Claude 连接与 Codex 初始化独立推进；版本探测与连接并行，版本结果不阻止连接可用。连接完成由主线程安装，只恢复对应 Agent/Runtime 的可用状态；原有草稿、历史待核验和未确认发送保护保留。历史列表在另一个 Agent 接入后补充该来源，正在读取的列表保留一次后续补读。

模型目录与技能目录都在当前会话空闲时预加载。模型缓存以 Agent、Runtime、cwd 为键共享结果及在途请求，最多 32 项，成功有效期 10 分钟，失败自动重试间隔 30 秒；手动重试立即读取。后台刷新保留已有模型列表，用户已选择的模型不因刷新而被覆盖。缓存仍仅存在于本进程。

Claude 的模型、默认模型和技能读取进一步共享同一个按目录缓存的临时探测进程：initialize 返回模型和命令，随后 get_skills_dialog 取得技能标记。模型结果在 initialize 完成后立即提供，不等待技能接口；技能失败不阻止读取已取得的模型。手动技能刷新和模型重试可以强制更新，共享中的请求保持去重。每次探测上限 30 秒，单个调用者取消只结束自己的等待；关闭 Client 取消全部探测并等待回收。正式任务的复用与回收见下节。

应用退出取消后台启动，等待加载器回收其自有连接；已经排入 UI 队列的迟到连接结果不再安装。发送前及原生身份写入后的关键检查点保持原有立即保存行为。

启动阶段验证见[启动与目录预加载](../verification/2026-10-30-startup-catalog.md)，全部优化的收尾验证见[性能收尾](../verification/2026-10-30-performance-completion.md)。

## 首条输出与交互派发

`internal/ui/event_batch.go` 对两种 Agent 使用同一派发规则：首条非空正文或工具记录、审批/提问请求、任务开始/结束、断线、错误和缺口事件立即刷新。遇到即时事件时，排在它之前的增量同批按原顺序应用。空助手和纯空白增量不消耗首条可见输出资格；不同 thread/turn/代次独立记录，索引上限 4096 项。

后续普通文字继续按 40 ms / 最多 256 条合并。每批仍等待主线程回调完成后再派发下一批，保持队列和 UI 工作量有界。这项优化移除应用层额外等待，不改变模型服务的首字耗时。

## Claude 连续对话进程

普通成功轮次收到完整 success/completed 原生 result 后立即保存终态，并保留已初始化进程供同会话下一轮复用。每轮创建独立 execution、TurnID、发送 UUID 和代次，审批标识与中断回调沿用原轮次归属。进程共享 reader、串行 writer 和控制响应表，旧轮次不能批准或结束新轮次。

空闲 2 分钟回收，最多保留 4 个空闲进程，超限回收最早空闲者；活动任务不参与淘汰。模型、CLI 文件、权限配置、凭据文件或直接关联的 CLAUDE/MCP 配置发生变化时，先回收旧进程，再重新 initialize/resume。本地 slash 命令、失败、中断及仍有后台工具的结果沿用有界排空后退出的路径，不保留该进程。空闲进程退出时，只有完整对话投影仍一致的记账变化才能更新原始摘要；实际对话变化继续阻止续发。

关闭应用取消并回收全部自有连接。复用失败发生在用户帧写入之前时保留未发送语义；写入不确定、无终态或坏帧保留 unknown，继续禁止重发。

## 技能候选

`internal/ui/completion_catalog.go` 在窗口可交互后的首次后台维护中预加载当前会话的技能目录，初始调度为 500 ms。有活动任务、连接失效、退出中或其他目录预加载尚未结束时，等待下一次维护；输入候选触发符仍可直接发起读取。同一目录已有请求时复用该请求。

目录缓存由应用持有，键为 Agent、Runtime 标识和会话 cwd；同键会话共享技能元数据与加载状态，技能选择、草稿和光标仍归属各自会话。缓存最多保留 32 项，优先淘汰最久未使用且已结束读取的项。成功的技能元数据另外原子保存于应用数据目录的 `catalog-cache/`，最多 32 项、单项最大 1 MiB；不包含对话、凭据或待处理审批。窗口创建后异步读取磁盘缓存，立即提供上次候选，同时强制向 Runtime 校验；磁盘读取不阻塞首个窗口，迟到的磁盘结果不覆盖已经完成的原生读取。刷新失败保留最近成功结果，损坏或超限缓存被忽略。模型列表缓存仍只在进程内有效。

成功结果有效期 10 分钟，失败后自动重试间隔 30 秒。过期或主动刷新时继续显示最近成功结果；刷新失败保留候选并显示错误，成功返回空目录时移除旧候选。候选浮层提供“刷新”和失败重试。Codex 普通首次读取发送 `forceReload=false`，过期刷新、文件失效刷新和手动刷新发送 `forceReload=true`。Claude 仍通过自己的临时 Runtime 目录读取路径获得可调用技能，不从本地扫描猜测可用性。

既有工作区监听收到 `SKILL.md`、`.claude/`、`.codex/` 变化时，将该工作区内 cwd 的缓存标记过期；读取过程中发生的新变化不会被旧请求的回调清除。监听仅覆盖现有已监听目录，全局目录或未展开目录中的外部变更由有效期与手动刷新兜底。异步结果只回写仍匹配缓存键的会话；关闭应用取消自有目录读取上下文，既有 Runtime 负责回收临时进程。

## 保存与维护

`internal/ui/maintenance.go` 将渲染和普通异步状态更新标记为待保存，首次标记后 1 秒执行快照比较与保存；后续更新合并到同一次保存，不延后这个截止点。发送前、取得原生会话 ID 后、任务终态、断线、项目元数据变更、关闭窗口及退出前仍立即保存。失败保留错误和重试截止点，发送前的关键保存失败仍阻止发送。

后台维护使用 MyGo 主线程派发，维护本身不要求重绘。无工作时默认间隔 30 秒；有待保存状态时按截止点唤醒，脏文件检查点间隔最多 500 ms，当前文件磁盘检查间隔 2 秒，已显示的 Git 工作区检查间隔 5 秒，退出等待间隔 250 ms。输入或异步更新通过合并的唤醒信号使长等待缩短到最多 500 ms。编辑器缓存整理及项目发现仍按 30 秒执行。无变化的文件检查不触发重绘和会话保存。

保存依旧使用原有 SQLite 事务、原子文件恢复副本和关键状态门控。此处只改变普通更新的保存频率，不将延迟保存当作已经完成的检查点。

## 长会话与文件事件

`internal/ui/session_resources.go` 在关闭 Codex 会话标签后保留 30 秒的复用窗口，随后由后台维护检查并回收。活动任务、待处理交互、恢复/分页/发送中的会话、未确认状态、外部写入者及未结束工具继续保留。回收前保存草稿、阅读位置、展开状态和会话标题；保存失败保留原 Runtime，并在 1 分钟后重试。原生状态不是 idle 或存在后台终端时保留资源，1 分钟后重新检查。

`internal/codex/idle.go` 先通过 `thread/read` 核对原生 idle，按 `thread/loaded/list` 与 `parentThreadId` 检查子孙会话，再用 `thread/backgroundTerminals/list` 确认没有后台终端，最后发送 `thread/unsubscribe`。子孙会话处于活动/未知状态或有后台终端时，保留父会话；尚未取得 turn ID 的会话也继续保留，避免卸载尚未产生可恢复 rollout 的新会话。Fuyu 自有 App Server 的启动参数设置 `thread_unload_delay_secs=0`，将取消订阅后的原生卸载等待设为 0 秒；用户的全局配置文件保持原值。应用自己的 30 秒复用窗口继续生效。其他连接仍持有订阅时，由 Runtime 处理资源归属。

确认取消订阅后，关闭会话释放消息投影、行句柄、列表和滚动缓存；本地会话、草稿、图片引用、模型选择与已保存的阅读信息继续保留。重开时恢复原生历史，恢复完成前暂停发送。卸载期间重开保留已有内容，等待卸载结果后恢复，避免 `resume`/`send` 与卸载并发。取消订阅响应不确定时先要求重新恢复，保留已有显示；原生检查失败时保留连接并在 1 分钟后重试。删除本地会话时也尝试回收其空闲 Runtime，取消订阅不归档或删除 CLI 原始历史。

该回收仅适用于实现相应可选能力的 Codex 后端；Claude 继续使用自身的 2 分钟空闲进程回收。真实 Codex 0.165.0 的隔离 MCP 进程回收及覆盖边界见[内存验证](../verification/2026-10-30-memory.md)。

`internal/ui/conversation_cache.go` 缓存会话的消息分组和阅读锚点投影。每次以消息身份、顺序、角色、轮次、工具类型/状态/父项、交互及影响可见性的空文本状态核对结构；普通文本增量保留原有行，界面通过消息引用读取最新文字。空助手开始输出、命令分组或文件变更分组变化、历史替换及裁剪会重建投影。正文 Markdown 继续使用 MyGo 自带的内容缓存和虚拟列表。

`internal/ui/workspace_changes.go` 将文件事件按实际路径合并，每批最多记录 4096 条路径，超过后进行该工作区全量核对。250 ms 合并定时器仅在有事件时启动；目录树按父目录去重刷新，只检查受影响的打开文件，目录改名/删除包含其子文件。读取中再次发生变化时保留一次后续文件/Git 检查，避免丢失最后一批变化。关闭、取消和工作区切换沿用原有上下文身份校验。

测试、性能样本和原生窗口证据见[性能验证](../verification/2026-10-29-performance.md)。
