# 开发指南

## 1. 当前状态与环境

当前仓库处于 P1 开始前，尚无 `go.mod`、应用源码、构建脚本或 CI 工作流。环境快照与下一动作维护在[实施计划](implementation-plan.md)，继续时重新核对。

第一轮工程初始化需要完成：

1. 核验本机 Go、Codex、macOS 开发环境及选定 MyGo 版本的要求。
2. 固定经过验证的 Go / MyGo 工具与依赖版本，记录对应配置文件。
3. 建立最小原生工程，实际运行后在本文记录启动、构建和测试命令。

当前所研究的 MyGo 提交要求 Go 1.27.1，见[参考核验](reference-verification.md)。这属于研究版本的要求，最终以项目锁定版本的配置为准。

## 2. 目录与代码定位

当前已存在的工程资料为根目录规范和 `docs/`。规划中的应用包见[设计文档](design.md)，责任划分见[子系统索引](subsystems/README.md)。

当某个包实际创建时，将入口文件、关键符号和对应验证方式补入子系统文档。先核对源码，再依据文档修改。

## 3. 验证方式

| 改动 | 应执行的验证 |
|---|---|
| 文档、规范或模板 | 链接、内容一致性、文件可见性、最终差异 |
| Go 逻辑 | 改动文件格式、相关测试；可用后运行完整测试与 vet |
| 协议与状态 | 请求/通知夹具、错误/断线/失效分支、实际版本兼容检查 |
| goroutine / 取消 / 进程 | 并发与 race 检查、退出及清理验证 |
| 原生 UI | 组件验证加真实窗口操作，覆盖输入法、焦点、滚动和缩放 |
| Codex 任务链路 | 临时工作目录中的真实调用、文件结果、原生终态和自有进程核验 |

工程初始化后，可按实际包结构核验以下标准 Go 命令；当前未执行，也不是已验证的构建入口：

```sh
go test ./...
go vet ./...
go test -race ./...
```

`gofmt` 作用于改动的 Go 文件。MyGo 的开发/打包命令在工具版本固定并运行成功后补入；存在条件不适用或环境缺失时，记录原因和未验证项。

## 4. 自动化与真实验收

自动化测试使用临时目录、受控子进程和协议夹具。使用 `t.Setenv` 等测试内机制隔离需要的配置路径；如测试框架需要独立 HOME，由测试启动器设置，保持开发者现有 shell 环境。隔离时保留可用的构建缓存路径。

真实 Codex 验收使用单独的临时工作目录，记录实际版本、有效设置、目录、操作和文件结果。复用已授权的原生登录方式，保持真实配置和凭据文件不变；日志与截图在保存前脱敏。

测试结束核对自有进程和必要清理。真实服务不可用时如实记录，夹具验证结果单独保留。

## 5. 验证记录与交接

实际验收后按需创建 `docs/verification/`，以“日期-主题.md”记录操作、输入、期望、实际结果和证据。协议/进程测试应记录失败分支；截图只用于证明对应的实际场景。

实现完成或中断前，按[实施计划](implementation-plan.md#7-中断后如何接续)更新接续点与工作记录。复现方法、当前自有进程、临时目录、已知问题和下一动作应可由另一位开发者直接接续。
