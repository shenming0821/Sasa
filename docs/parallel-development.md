# 并行开发与任务目录回收

开发任务使用独立 Git worktree，主目录串行完成集成、公共 Preview 验收及正式版发布。不限制并发数量，任务目录在交付后自动回收。

## 创建与开发

在主目录执行：

```sh
./scripts/task-worktree create session-search
./scripts/task-worktree list
```

创建的任务目录位于主目录同级的 `Sasa.worktrees/session-search`，分支为 `task/session-search`，从主目录当前 `HEAD` 创建。主目录的未提交修改不会复制进去；任务依赖尚未提交的基础变更时，先协调依赖与提交授权。

同一需求的反馈、视觉调整和修复继续在原任务目录开发和验收。独立需求、需要并行隔离的验证或已回收任务的后续修改可新建目录。

在任务目录中修改代码，运行相关自动化测试，保持公共 Preview 由主目录管理。`scripts/build`、`scripts/run-preview` 和 `scripts/promote` 检查调用目录，开发 worktree 不能通过这些入口替换公共应用。此边界同时适用于 Codex 与 Claude 开发会话。

普通开发保留工作区修改。开发完成后交接任务名、目录、改动范围、自动化结果和待验收操作，报告“开发完成，待集成验收”。任务会话停止写入后，由集成会话接手；继续修改时协调归属。

## 集成验收

用户说“集成验收”时，在主目录运行：

```sh
./scripts/preview-task session-search
```

脚本核对已登记的任务目录和实际分支，用主目录当前提交和该任务相对共同祖先的完整改动构造临时源码目录。输入包括任务提交、工作区最终内容及未忽略的新增文件。主目录尚未提交的文件和其他任务目录不参与构建。命令显示改动范围；若与主目录提交冲突，在任务目录处理后再试。

构建和启动使用同一构建 ID，唯一的公共验收入口是主目录的 `bin/Sasa Preview.app`。源码组合、构建或启动失败时，临时源码目录自动清理，主目录与任务目录的源码及 Git 暂存状态保持原样。窗口可用后，实际操作本次功能，再报告原生结果。需要调整时继续在同一任务目录迭代。

## 发布

用户说“发布”后，在授权范围内提交，将任务分支 rebase 到主分支并快进合入，再从主目录登记和验证最终版本：

```sh
./scripts/task-worktree integrated session-search
./scripts/build preview
./scripts/run-preview <构建ID>
./scripts/promote <构建ID>
```

登记要求任务工作区干净、存在任务提交，且任务 `HEAD` 是主目录 `HEAD` 的祖先，两者之间不存在 merge 提交。登记保存变基后的任务提交和集成提交；线性合入保持祖先关系，供发布后自动回收核验。脚本本身不暂存、提交或合并代码。

晋升前核对候选记录的源码提交和摘要。已有验收候选与最终提交及内容一致时可直接使用该构建 ID；需要重新构建时先完成公共 Preview 验证。正式版安装后推送当前分支，推送失败时继续处理并核验远端。

## 发布后回收

`./scripts/promote <构建ID>` 成功完成默认正式版安装后，自动检查登记任务并回收。延迟生效安装成功即为此处的“发布成功”，无需退出或重启正在使用的正式版。发布流程继续推送当前分支。

回收同时核验：

- 最新成功发布回执、当前安装身份及完整应用文件清单一致。
- 发布候选源码摘要与其源码提交的完整内容一致，能够证明候选由已提交版本构建。
- 发布源码提交包含任务登记的集成提交。
- 任务目录、分支和 `HEAD` 与登记一致，没有未提交或未跟踪内容，且 worktree 未锁定。

满足条件时使用普通 `git worktree remove` 移除任务目录及其被忽略缓存，保留 Git 分支与提交，以及位于 Git 公共目录 `sasa-tasks/tasks.json` 的生命周期记录。未满足条件时打印原因并保留目录，回收失败不撤销已经完成的发布。

发布结束前，逐项核对本次开发和验收创建的临时资源。先退出本次启动的测试进程并撤销临时注入，再清理测试用的脚本、夹具、隔离数据、日志、临时目录及无保留用途的构建产物。以实际进程和路径核验清理结果。保留用户数据、其他任务的资源、公共 Preview、发布回执和回滚所需材料。

新建任务前自动补做回收，也可以在主目录手动重试：

```sh
./scripts/task-worktree cleanup
```

发布预检 `--check`、使用 `--app` 或 `--data-dir` 的隔离晋升不会触发回收。未提交源码构建的候选无法通过完整提交核验，任务保留到后续可核验的发布。暂停、取消或未交付任务继续保留；需要放弃未交付内容时按用户明确指令处理。

## 磁盘边界

任务源码共享 Git 对象库，缓存和构建产物属于各自目录。开发目录按相关测试需要生成缓存，Preview 候选集中在主目录。任务目录回收会释放其本地缓存；主目录历史候选的保留与清理属于独立的发布产物管理，不随任务回收删除。

管理脚本验证入口：

```sh
python3 -B -m unittest discover -s scripts -p 'test_task_worktree.py'
python3 -B -m unittest discover -s scripts -p 'test_preview_task.py'
```
