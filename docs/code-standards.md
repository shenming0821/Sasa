# 代码标准

本文用于实现与审核，覆盖 Fuyu 当前的 Go、原生 UI、Codex 协议和进程边界。阶段范围以[实施计划](implementation-plan.md)为准。

## 1. 变更与职责

- 一次变更围绕一个目标；先明确触发条件和可观察结果，再追踪输入、状态、调用者及副作用。
- 修复时搜索相同判断和相邻分支，覆盖同类缺陷；保留范围之外的既有行为。
- 已有功能的内部整理保持契约稳定；需要改变契约时，同步更新[设计说明](design.md)和相关验证。
- 按实际需要建立包与接口。当前区分 UI、应用状态、Codex 客户端和进程管理；遇到第二个真实实现时再提炼共同抽象。
- 现有模块先核对实际源码，文档中的规划路径在实现后补充源码链接。

## 2. Go 与并发

- Go 文件使用 `gofmt`，命名表达业务含义，注释说明必要的原因、约束和资源归属。
- 错误保留操作上下文，读取或解析失败表达为未知/失败状态，保留可用的原数据。
- 为 goroutine、timer、channel 和子进程明确创建者、取消范围与结束条件。
- 持锁期间只做必要状态操作；可能等待的通信、进程调用和用户交互放在锁外。
- 后台事件通过 MyGo 认可的主线程更新机制修改 UI 状态。
- 涉及共享状态、异步回调和取消的修改，运行相关并发测试与 race 检查。

## 3. 原生 UI

- 优先使用项目既有 MyGo 组件与视觉模式，交互中显示实际目录、运行状态和错误。
- 输入法组合期间保留输入语义；发送、换行、停止、焦点与键盘操作在真实窗口验证。
- 消息和工具卡片按稳定 ID 更新；用户向上阅读后保留位置，主动返回末尾时再恢复跟随。
- 流式输出做批量刷新，大日志可折叠并限制缓存；输入、滚动与停止保持可操作。
- 产品界面展示对用户有用且已实现的能力；样例标记和协议调试信息放入开发验证场景。

## 4. Codex 与状态

- 以实际安装版本的官方协议、schema 和运行结果确定字段含义，记录版本及来源。
- 分别维护连接、thread、turn 和待处理交互；RPC 成功、文字结束和进程退出分别核验其含义。
- 客户端请求、服务端请求、通知、响应和错误分流处理；用户等待期间协议读取仍持续进行。
- 审批和问题表单响应对应的原生请求，保留其 ID、决定范围和问题结构。
- 请求已解决、turn 结束或连接失效时，按原生结果更新入口有效性，防止重复响应。
- 本地序号仅用于本地排序；使用原生 ID 和快照核对恢复结果。
- `turn/start` 响应丢失时先核验原生状态，再决定后续动作，避免重复执行。
- 保留用户原生配置，仅覆盖明确选择的设置；运行状态显示实际生效值。

## 5. 进程与文件

- 参数以独立列表传给进程；每个会话明确 cwd，并在活动执行期间保持绑定。
- 只管理 Fuyu 拥有且能确认身份的进程；停止共享进程前展示全部受影响会话。
- 区分原生中断、应用进程清理和连接丢失，核验实际终态后更新结果。
- 文件操作检查目标范围；路径、权限和解析错误保留其具体原因。
- 索引和缓存写入保证可恢复性；读取失败时保留原记录，必要的替换采用临时文件与原子更新。
- 日志、数据库和证据脱敏，秘密输入和凭据保留在其原有受保护来源。

## 6. 验证

- 按用户可观察的行为设计测试；协议样本来自真实 schema 或脱敏事件，保留缺字段、空值和错误样本。
- 自动化测试使用临时配置与受控输入，避免读取真实凭据或访问真实模型服务。
- 测试启动的进程、goroutine 与定时器在测试结束时取消并等待退出。
- 并发测试等待可观察状态；时间相关逻辑优先使用可控时钟或同步点。
- 缺陷修复的回归测试应能识别原缺陷；仅在必要且可隔离的条件下验证修复前后差异。
- 真实 Codex 与原生窗口验收单独记录。代码构建、协议夹具通过和真实运行通过各自说明。
- 文档或格式调整按影响核验内容与差异；验证命令的可用条件见[开发指南](development.md)。
